## 协程（goroutine）

Goroutine（协程）和 Channel（通道）是 Go 实现并发的两大基石。

Goroutine 是由 Go Runtime（运行时）管理的用户态轻量级“线程”，是 Go 并发执行的最小单位。与内核态 OS 线程相比，Goroutine 启动快、占用内存少，创建和销毁开销极低，数量可达数十万甚至上百万。

创建 Goroutine 语法：`go f(x,y,z)`，关键字 go 会启动一个新的 Goroutine 并发执行 f 函数体。注意：f、x、y、z 的求值发生在当前 Goroutine 中，f 函数体的执行则发生在新的 Goroutine 中。

程序启动时，`main()` 函数即在一个单独的 Goroutine 中运行，称为 Main Goroutine。Main Goroutine 结束时所有其它 Goroutine 也被强制终止，需用 `sync.WaitGroup` 或 Channel 协调。

Go 不提供强制终止其它 Goroutine 的能力，没有 `kill(Goroutine)` 或 `stop(Goroutine)` 这样的函数。每个 Goroutine 必须有明确的退出路径（自然结束或通过 context/Channel 发送取消信号），否则可能造成泄露。

```go
func say(s string) {
 for range 3 {
  fmt.Println(s)
 }
}

func main() {
 // 子 Goroutine 与 Main Goroutine 并发执行
 go say("world")
 say("hello")

 // 这里仅为示例，生产环境请使用 sync.WaitGroup 或 Channel 进行同步，不然 Main Goroutine 结束后整个程序会退出
 for runtime.NumGoroutine() != 1 {
  time.Sleep(time.Millisecond)
 }
}
```

当然，也可以并发执行一个方法：

```go
type Rectangle struct {
 width, height float64
}

func (r Rectangle) Area() float64 {
 area := r.width * r.height
 fmt.Println(area)
 return area
}

func main() {
 rect := Rectangle{width: 3, height: 4}
 go rect.Area()

 for runtime.NumGoroutine() != 1 {
  time.Sleep(time.Millisecond)
 }
}
```

旋转动画示例：

```go
func main() {
 go spinner(200 * time.Millisecond)
 const n = 45
 fibN := fib(n) // slow
 fmt.Printf("\rFibonacci(%d) = %d\n", n, fibN)
}

func spinner(delay time.Duration) {
 for {
  for _, r := range `-\|/` { // 反引号表示原始字符串字面量
   fmt.Printf("\r%c", r) // \r 表示回车，它的作用是将光标移动到当前行的开头，而不换行。这意味着在输出新的字符时，会覆盖当前行的内容。
   time.Sleep(delay)
  }
 }
}

func fib(x int) int {
 if x < 2 {
  return x
 }
 return fib(x-1) + fib(x-2)
}
```

在 Main Goroutine 中阻塞等待子 Goroutine 退出的方法：

- 使用 `sync.WaitGroup` 等待多个子 Goroutine 退出
- 或添加一个 Channel `done := make(chan struct{})`，在 Main Goroutine 中 `<- done` 阻塞等待 Channel 可读，子 Goroutine 执行完毕时关闭这个通道 `defer close(done)` 触发 Channel 可读

启动多个 Goroutine 并用 WaitGroup 等待它们都执行完毕：

```go
func work(id int) {
 fmt.Printf("Worker %d starting\n", id)
 time.Sleep(time.Second) // 模拟耗时工作
 fmt.Printf("Worker %d done\n", id)
}

func old() {
 // 传统写法 (Go 1.25 之前)
 var wg sync.WaitGroup // WaitGroup 是一个结构体
 for i := range 5 {
  wg.Add(1) // 启动一个 Goroutine 前，计数器加 1
  go func(i int) {
   defer wg.Done() // 确保在函数退出时通知 wg 任务完成，计数器减 1
   work(i)
  }(i)
 }
 wg.Wait() // 阻塞，直到所有 Goroutine 都调用了 Done()，即计数器归零
}

func modern() {
 // Go 1.25 新写法
 var wg sync.WaitGroup
 for i := range 5 {
  wg.Go(func() { // 一行代码替代 Add+Done 样板代码
   work(i)
  })
 }
 wg.Wait()
}

func main() {
 old()
 modern()
}
```

一个程序中的所有 Goroutine 在相同的地址空间中运行，对共享内存（变量）的访问必须同步（如通过 `sync.Mutex`、`sync.RWMutex`等同步原语）。可使用 `go run -race` 或 `go test -race` 检测数据竞争。

```go
var (
 counter int // 全局变量，所有 Goroutine 共享
 mu      sync.Mutex
)

func increment() {
 mu.Lock()
 counter++ // 临界区
 mu.Unlock()
}

func main() {
 var wg sync.WaitGroup

 for range 1000 {
  wg.Go(func() {
   increment()
  })
 }

 wg.Wait()
 fmt.Printf("counter = %d\n", counter) // 永远输出 1000
}
```

### G-M-P 调度模型

M:N 线程模式：将 M 个用户态线程（Goroutine）动态地映射到 N 个内核态 OS 线程上执行的一种模型。

Go 在有限的 OS 线程上高效并发运行成千上万个 Goroutine 的秘密在于其用户态的调度器，该调度器采用 G-P-M 模型，将 G 分配到 P 和 M 上执行。这三个字母分别代表：

- G (Goroutine)：代表一个 Goroutine，是一个独立的执行单元（包含栈、状态等）。在 Go 运行时内部，每个 Goroutine 都由一个类型为 g 的结构体实例表示（源代码：`${GOROOT}/src/runtime/runtime2.go`）
- P (Processor)：逻辑处理器，可以看作调度所需的上下文资源，负责调度 G 到 M。P 负责维护一个本地的 Goroutine 运行队列 (runqueue)。P 的数量默认等于当前机器的逻辑 CPU 核心数，可通过 `runtime.GOMAXPROCS(n)` 或 `GOMAXPROCS` 环境变量设置，它决定了真正的并发度（即同时运行的 G 数量），一般使用默认值即可。当 `GOMAXPROCS` > 逻辑 CPU 核心数时，Go 运行时会创建额外的 OS 线程，通过时间片轮转让多个线程竞争 CPU 资源，可能导致更多的上下文切换，性能反而下降
- M (Machine)：代表一个 OS 线程（最多 10000 个），是最终在 CPU 上执行代码的实体，所有的 Go 代码最终都是由 M 来执行的

这个模型的关键在于，P 作为中间层，将 G（任务）和 M（执行者）动态地关联起来。M 不直接接触 G，一个 M 必须持有一个 P 才能执行 G。这种设计解耦了 G 和 M，减少了早期版本中因全局锁和资源竞争带来的性能损耗。

```text
        ┌────────────────┐
        │   Global Queue │  ← 存放全局可运行的 G
        └──────┬─────────┘
               │
    ┌──────────┴──────────┐
    │                     │
┌────────────────┐     ┌───────────────┐
│   P1           │     │   P2          │   ← 每个 P 管理一个本地 G 队列
│  ┌──────────┐  │     │  ┌──────────┐ │
│  │ G1,G2,G3 │  │     │  │ G4,G5,G6 │ │
└──┴──────────┘──┘     └──┴──────────┘─┘
    │                      │
┌────────────┐           ┌────────────┐
│   M1       │           │   M2       │
│  OS thread │           │  OS thread │
└────────────┘           └────────────┘
```

每个 M 运行一个调度循环：

for {
    if 有可运行的 G {
        运行 G.run()
    } else {
        尝试从全局队列/其它 P 窃取任务
    }
}

完整过程：

增加：go 关键字创建 G，todo，选择一个 P，放入 P 的本地队列？如果本地队列满了，放入全局队列？todo

1. M 绑定一个 P
   - 只有绑定了 P，M 才能执行 Go 代码
   - 每个 P 有自己的 Goroutine 队列（local runq）

2. P 从本地队列取 G 执行
   - 无锁 FIFO 结构（数组环形队列）
   - 若本地队列为空，P 会从全局队列或其它 P 的队列中窃取 G 来执行（work stealing 工作窃取）
   - 如果 P 任务太多，部分 G 会分给全局队列 todo

3. 执行 Goroutine（G）
   - 如果 G 进入阻塞式系统调用（如文件 I/O）：
     - 当前 M 随 G 进入阻塞
     - P 与当前 M 解绑并移交给可用的 M（或新建一个 M），让队列中的其它 G 继续执行（hand off 剥离离场）
     - 系统调用返回后，若原 P 空闲（未被其它 M 占用）则旧 M 重新获得 P，否则 G 放回全局队列等待调度
   - 如果 G 在 Channel/锁等操作上阻塞：
     - G 被挂起到等待队列
     - M 和 P 不分离，调度器从 P 的本地队列取下一个 G 继续执行

4. G 结束或被挂起
   - M 将返回 P 的调度循环，继续取下一个 G

Goroutine 运行状态包括：_Grunnable（就绪，在 runqueue 中）、_Grunning（运行中，绑定 M 和 P）、_Gsyscall（系统调用中）、_Gwaiting（阻塞等待某个事件或资源）、_Gdead（已终止）。

当一个 Goroutine 因时间片用完、执行阻塞操作（如 Channel 操作、系统调用）或主动让出 CPU 时，调度器会将其当前的寄存器状态（如程序计数器 PC- 指向了下一条要执行的指令，栈指针 SP）保存到 sched（类型为 gobuf）结构体中。随后，调度器会加载另一个 Goroutine 的 sched 信息到寄存器，实现切换。整个过程完全在用户态由 Go 运行时完成，开销远小于陷入内核的 OS 线程上下文切换。

抢占式调度：在 go 1.14+ 版本中，如果一个 Goroutine 持续运行过长时间（> 10 ms），调度器会设置其 preempt 标记，或在安全点发送异步抢占信号，强制它让出 CPU，从而防止单个 Goroutine 长时间占用计算资源导致其它 Goroutine“饿死”。

### Goroutine 栈管理

每个 Goroutine 都有自己独立的栈空间。每个 Goroutine 在创建时仅分配 2KB 的初始栈空间，但可以动态增长，最大可以到 1GB。stack.hi 指向栈的高地址端（栈底），而 stack.lo 指向栈的低地址端（栈顶），Goroutine 的栈在内存中向低地址方向增长。这意味着，当发生函数调用需要分配更多栈空间时，栈指针 SP 会向 stack.lo（低地址）方向移动。结构体 stack 中的 lo 和 hi 字段精确地定义了当前 Goroutine 栈内存的起始（低地址）和结束（高地址）边界，即 `[stack.lo, stack.hi)`。

Go 运行时使用 stackguard0 字段来高效地管理栈空间，实现自动扩容。其工作机制如下：

- 警戒线设置：在正常情况下，stackguard0 的值会被设置为 stack.lo + StackGuard（StackGuard 是一个安全保护区大小）
- 溢出检查：在函数调用的前奏（prologue）中，运行时会比较当前的栈指针 SP 和 stackguard0。如果 SP 的值小于 stackguard0（因为栈向低地址增长），就意味着栈空间即将不足
- 触发扩容：一旦检测到栈空间不足，运行时就会触发栈的扩容操作。这会分配一块更大的新内存区域，将原有栈的内容复制过去，并更新 stack.lo、stack.hi 以及 stackguard0 等字段的值
- 抢占信号：stackguard0 还有一个重要作用是实现协作式和基于信号的抢占调度。当需要抢占当前正在执行的 Goroutine 时，运行时会将其 stackguard0 的值设置为一个特殊的常量 StackPreempt。这样，在下一次栈检查时，就会触发抢占流程，而并非真正的栈扩容

Go 运行时也会在适当的时候自动收缩栈空间。Go 的栈收缩是在 GC 期间由运行时检查并执行的，如果发现 Goroutine 的栈使用量大幅低于当前大小才会收缩，而不是在每一个函数返回后自动完成的实时收缩。
