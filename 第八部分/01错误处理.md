## error 错误处理

Go 的错误处理采用显式返回错误的方式，而非异常处理机制。

Go 使用 error 接口变量表示错误信息。error 是内置接口类型，其中定义了 `Error() string` 方法，返回错误的字符串描述。

```go
type error interface {
    Error() string
}
```

虽然 error 接口名称首字母小写，但它是预定义标识符，属于“宇宙块”，不需要导入就可以直接使用。

函数通常返回一个 error 接口变量 err，nil 表示成功，非 nil 表示失败。

```go
func f() {
 i, err := strconv.Atoi("42") // 错误变量通常命名为 err/Err，或以 err/Err 开头，例如 errNotFound 
 if err != nil {
  fmt.Printf("couldn't convert number: %v\n", err) // 底层调用 Error() 方法获取错误描述
  return
 }
 fmt.Printf("Converted integer: %d\n", i)
}
```

调用一个函数时，通常将处理失败的逻辑放在处理成功的逻辑之前。如果某个错误会导致函数返回，那么处理成功的代码不应放在 else 语句块中，而应直接放在函数体中，减少缩进。

```go
// OK — 错误先处理，成功后无缩进
if err != nil {
    return err
}
// 成功逻辑在主流程

// 不好 — 不必要的 else 增加缩进
if err == nil {
    // 成功
} else {
    return err
}
```

不应忽略错误，应记录错误或向上返回（原样返回或用 `%w` 包装后返回）。错误通常只应处理一次，不应既记录又向上返回，因为更靠上的调用方也可能类似这样处理同一个错误，导致日志中产生大量噪音。

### 检查错误的几种方法

- 将 error 变量与 nil 比较
- [func errors.Is(err, target error) bool](https://pkg.go.dev/errors#Is)：检查 err 错误链中有没有出现过 target 这个特定错误值，会沿着 `%w` 包装链逐层比较
- [func errors.AsType[E error](err error) (E, bool)](https://pkg.go.dev/errors#AsType)：查找 err 错误链中第一个匹配错误类型 E 的错误，找到则返回该错误值和 true，否则返回类型 E 的零值和 false
- [func errors.As(err error, target any) bool](https://pkg.go.dev/errors#As)：检查 err 错误链中有没有属于 target 这个类型的错误，有的话，把它的结构化信息提取出来。As 与 AsType 等效，请优先使用 AsType（泛型，类型安全，编译期检查）

#### `errors.Is`：按错误值匹配（`==` 语义）

核心逻辑：在错误链中寻找与 `target` 相等的错误值，找到后返回 true，停止。

匹配规则（按优先级）：

| 步骤 | 说明 |
| -- | -- |
| 1 | `err == target`？直接 `==` 比较 |
| 2 | err 实现了 `Is(target error) bool`？调用它，让错误自己判断 |
| 3 | `err = Unwrap(err)`，沿链向下一层，重复步骤 1 |

#### `errors.As`：按错误类型匹配（反射）

核心逻辑：在错误链中寻找第一个类型匹配的错误，找到后赋值给 `target`，返回 true，停止。

匹配规则（按优先级）：

| 步骤 | 说明 |
| -- | -- |
| 1 | err 的具体类型是否可赋值给 target 指向的类型？用反射检查 |
| 2 | err 实现了`As(target interface{}) bool`？调用它 |
| 3 | `err = Unwrap(err)`，沿链向下一层，重复步骤 1 |

#### 示例

```go
func main() {
 if _, err := os.Open("non-existing"); err != nil {
  if errors.Is(err, fs.ErrNotExist) { // true
   fmt.Println("file does not exist")
  } else {
   fmt.Println(err)
  }
 }

 if _, err := os.Open("non-existing"); err != nil {
  var pathError *fs.PathError
  if errors.As(err, &pathError) { // true，第二个参数 target 是要匹配的错误类型 *fs.PathError 的地址
   fmt.Printf("Failed at path: %s\n", pathError.Path)
  } else {
   fmt.Println(err)
  }
 }

 if _, err := os.Open("non-existing"); err != nil {
  if pathError, ok := errors.AsType[*fs.PathError](err); ok { // true，用 AsType 更直观
   fmt.Printf("Failed at path: %s\n", pathError.Path)
  } else {
   fmt.Println(err)
  }
 }
}
```

### 创建错误的方式

#### 两种基本方式

Go 标准库提供了两种基本的创建 error 的方式：通过 `errors.New` 或 `fmt.Errorf` 返回 error 值，底层类型是 `*errors.errorString`、`*wrapError`或 `*wrapErrors`，它们都实现了 error 接口。

- `*errors.errorString`：`errors.New` 或 `fmt.Errorf 不带 %w` 时返回
- `*wrapError`：fmt.Errorf 带一个 `%w` 时返回
- `*wrapErrors`：fmt.Errorf 带多个 `%w` 时返回

每次调用 `errors.New` 都会返回一个唯一的错误值，即使参数相同。`fmt.Errorf` 在不使用 `%w` 时内部也是调用 `errors.New`。

```go
func main() {
 if result, err := sqrt(-1); err == nil { // 实际代码中应当先检查 err 是否为 nil，这里仅为示例
  fmt.Println(result)
 } else {
  fmt.Println(err) // sqrt: negative number
 }

 if result, err := sqrt(4); err == nil {
  fmt.Println(result) // 2
 } else {
  fmt.Println(err)
 }

 err1 := errors.New("an error")
 fmt.Printf("(%[1]T, %[1]v)\n", err1) // (*errors.errorString, an error)
 err2 := errors.New("an error")
 fmt.Printf("(%[1]T, %[1]v)\n", err2) // (*errors.errorString, an error)
 if errors.Is(err1, err2) {           // false，即使 err1 和 err2 的错误信息相同，也会返回 false，因为它们是不同的实例
  fmt.Println("err1 包含 err2")
 }
 if err1 == err2 { // false，即使 err1 和 err2 的错误信息相同，也会返回 false，因为它们是不同的实例
  fmt.Println("err1 等于 err2")
 }

 err3 := fmt.Errorf("an error")
 fmt.Printf("(%[1]T, %[1]v)\n", err3) // (*errors.errorString, an error)
 err4 := fmt.Errorf("an error")
 fmt.Printf("(%[1]T, %[1]v)\n", err4) // (*errors.errorString, an error)
 if errors.Is(err3, err4) {           // false，即使 err3 和 err4 的错误信息相同，也会返回 false，因为它们是不同的实例
  fmt.Println("err3 包含 err4")
 }
 if err3 == err4 { // false，即使 err3 和 err4 的错误信息相同，也会返回 false，因为它们是不同的实例
  fmt.Println("err3 等于 err4")
 }

 const name, id = "bimmler", 17
 err := fmt.Errorf("user %q (id %d) not found", name, id) // 返回一个格式化的 error 值
 if err != nil {
  fmt.Println(err) // user "bimmler" (id 17) not found
 }
}

func sqrt(f float64) (float64, error) {
 if f < 0 {
  return 0, errors.New("sqrt: negative number") // 返回一个 error 值。只能接收一个 string 参数，不如 fmt.Errorf 灵活
 }

 return math.Sqrt(f), nil
}
```

错误值比较通常用 `errors.Is` 而不是 `==`。如果调用者需要匹配并处理错误值，则需要将错误值赋值给变量以支持与 `errors.Is` 匹配。错误变量一般以 err/Err 开头。

```go
var ErrCouldNotOpen = errors.New("could not open") // 将错误值赋值给变量用于匹配，错误变量一般以 err/Err 开头

func Open() error {
 return ErrCouldNotOpen
}

func main() {
 if err := Open(); err != nil {
  if errors.Is(err, ErrCouldNotOpen) { // true
   // handle the error
   fmt.Println("could not open")
  } else {
   fmt.Println("unknown error")
  }
 }
}
```

#### 自定义错误类型

除了通过 `fmt.Errorf` 和 `errors.New` 创建错误值外，还可以自定义错误类型，自定义错误类型需要实现 error 接口，类型名一般以 Error 结尾。

```go
// 自定义错误类型，类型名以 Error 结尾
type NegativeSqrtError float64

// 实现 error 接口，返回错误的字符串描述
func (err NegativeSqrtError) Error() string { // 方法接收者为值类型，意味着值类型 NegativeSqrtError 和 指针类型 *NegativeSqrtError 都实现了 error 接口
 return fmt.Sprintf("cannot Sqrt negative number: %v", float64(err)) // 将 err 转换为 float64，否则陷入无限递归
}

func Sqrt(x float64) (float64, error) { // 返回值使用 error 接口类型
 if x < 0 {
  return 0, NegativeSqrtError(x) // 返回具体的实现。这里将 float64 类型的 x 强制转换为 NegativeSqrtError 类型
 }

 return math.Sqrt(x), nil
}

func main() {
 result, err := Sqrt(2)
 fmt.Printf("%v, %v\n", result, err) // 1.4142135623730951 nil
 result, err = Sqrt(-2)
 fmt.Printf("%v, %v\n", result, err) // 0 cannot Sqrt negative number: -2

 err = NegativeSqrtError(-2)
 fmt.Println(err) // cannot Sqrt negative number: -2
}
```

需要注意：在 `Error()` 方法内部调用 `fmt.Sprintf("%v", err)` 会导致死循环！其原因是 fmt.Sprintf 检测到 err 实现了 error 接口，会调用 `err.Error()` 获取 err 的字符串表示，而 `err.Error()` 的实现中又调用了 `fmt.Sprintf`，导致无限递归。

```go
type MyError struct{ Msg string }

// 实现 error 接口
func (err *MyError) Error() string { // 方法接收者为指针类型，意味着仅指针类型 *MyError 实现了 error 接口
 return fmt.Sprintf("MyError: %s", err)
 // return fmt.Sprintf("MyError: %s", err.Msg) // 使用结构体字段进行格式化：return fmt.Sprintf("MyError: %s", err.Msg)，这样打印指针就不会死循环了
}

func main() {
 err := MyError{"hello"}
 fmt.Println(err)  // 打印值不会死循环（因为值类型 MyError 没有实现 Error() 方法）
 fmt.Println(&err) // 打印指针会死循环（因为指针类型 *MyError 实现了 Error() 方法）
 // 注意：如果 Error() 方法接收者是值类型，意味着值类型 MyError 和 指针类型 *MyError 都实现了 error 接口，那么打印值、指针均会死循环
}
```

当一个类型同时实现 fmt.Stringer 和 error 接口时，fmt 包在格式化时会调用 `Error()` 方法，而忽略 `String()` 方法。这样设计的目的是为了优先暴露错误信息，避免关键的错误细节被自定义的字符串格式覆盖掉。另外，如果类型实现了 fmt.Formatter 接口（即自定义 `Format(f State, verb rune)` 方法），则这个优先级最高，会覆盖 `Error()` 和 `String()` 的调用。

```go
type MyError struct {
 Name string
}

// 实现 error 接口
func (m MyError) Error() string {
 return "Error(): something went wrong"
}

// 实现 fmt.Stringer 接口
func (m MyError) String() string {
 return "String(): " + m.Name
}

func main() {
 err := MyError{Name: "Go"}

 // 1. 使用 %v 和 %s：优先调用 Error()
 fmt.Printf("%v\n", err) // 输出：Error(): something went wrong
 fmt.Printf("%s\n", err) // 输出：Error(): something went wrong

 // 2. 使用 %#v（Go 语法表示）：不会调用 Error 或 String，直接输出 Go 语法结构
 fmt.Printf("%#v\n", err) // 输出：main.MyError{Name:"Go"}

 // 3. 想要强制调用 String() 怎么办？需要手动类型断言或显式调用
 fmt.Println(err.String()) // 输出：String(): Go
}
```

`errors.AsType` 匹配自定义错误：

```go
// 自定义错误类型，类型名以 Error 结尾
type CouldNotOpenError struct {
 File string
}

// 实现 error 接口
func (e *CouldNotOpenError) Error() string { // 方法接收者为指针类型，意味着仅指针类型*CouldNotOpenError 实现了 error 接口
 return fmt.Sprintf("could not open file %q", e.File)
}

func Open(file string) error {
 return &CouldNotOpenError{File: file} // 实现 Error 方法时的接收者是指针类型，只能将指针类型*CouldNotOpenError 的变量赋值给 error 接口变量
}

func main() {
 if err := Open("testfile.txt"); err != nil {
  if errCouldNotOpen, ok := errors.AsType[*CouldNotOpenError](err); ok { // true，*CouldNotOpenError 类型实现了 error 接口
   // handle the error
   fmt.Println(errCouldNotOpen)
  } else {
   fmt.Println("unknown error")
  }
 }
}
```

#### `%w` 错误包装与 Unwrap 解包

go1.13 之后，`fmt.Errorf` 支持 `%w` 动词创建包装错误（wrapped error）。`%w` 会生成一个“包装了原始错误”的新错误，这个新错误保留了原始错误的类型和信息，形成错误链，支持 `errors.Unwrap()`，并支持后续使用 `errors.Is` 和 `errors.AsType` 进行匹配。

```go
// 没有 %w 之前（用 %v）：
err := os.ReadFile("not-exist.txt") // 返回 os.ErrNotExist
return fmt.Errorf("read config failed: %v", err) // %v 表示格式化错误，不会保留原始错误信息
// 上层使用 errors.Is(err, os.ErrNotExist) 会返回 false，因为原始错误被“抹掉”了

// 有了 %w 之后：
err := os.ReadFile("not-exist.txt")
return fmt.Errorf("read config failed: %w", err)
// 上层可以正常通过 errors.Is(err, os.ErrNotExist) 判断是否为 os.ErrNotExist 错误
```

[func Unwrap(err error) error](https://pkg.go.dev/errors#Unwrap)：如果参数 err 有`Unwrap() error`方法，则调用该方法解包并返回上一层错误；否则返回 nil。注意：Unwrap 不会解包 `errors.Join` 返回的错误。

```go
func main() {
 // 示例 1: 基本的错误包装
 err := processFile("not-exist.txt")
 fmt.Printf("包装后的错误：%v\n", err) // 包装后的错误：处理文件失败：open not-exist.txt: no such file or directory

 // 示例 2: 使用 errors.Is 检查错误链
 if errors.Is(err, os.ErrNotExist) {
  fmt.Println("底层错误值是 os.ErrNotExist") // 底层错误值是 os.ErrNotExist
 }

 // 示例 3: 使用 errors.As 提取特定类型的错误
 if pathError, ok := errors.AsType[*os.PathError](err); ok {
  fmt.Printf("详细信息：操作：%v，路径：%v，错误：%v\n", pathError.Op, pathError.Path, pathError.Err) // 详细信息：操作：open，路径：not-exist.txt，错误：no such file or directory
 }

 // 示例 4: 多层错误包装
 err = processData()
 fmt.Printf("多层包装后的错误：%v\n", err) // 多层包装后的错误：处理数据失败：读取配置失败：open /not/exist/file.txt: file does not exist

// 示例 5: 遍历错误链
 fmt.Println("遍历错误链：")
 for unwrapped := err; unwrapped != nil; unwrapped = errors.Unwrap(unwrapped) {
  fmt.Printf("  - 类型：%[1]T，值：%[1]v\n", unwrapped)
 }
 // 遍历错误链：
 //   - 类型：*fmt.wrapError，值：处理数据失败：读取配置失败：open /not/exist/file.txt: file does not exist
 //   - 类型：*fmt.wrapError，值：读取配置失败：open /not/exist/file.txt: file does not exist
 //   - 类型：*fs.PathError，值：open /not/exist/file.txt: file does not exist
 //   - 类型：*errors.errorString，值：file does not exist
 // 上述遍历错误链打印了四层，是因为 *os.PathError 也有 Unwrap 方法，得到 *errors.errorString，*errors.errorString 没有 Unwrap 方法，所以遍历到 *errors.errorString 时，返回 nil，循环就结束了
}

// 基础示例函数
func processFile(filename string) error {
 _, err := os.Open(filename)
 if err != nil {
  fmt.Printf("原始错误：%[1]v, 类型：%[1]T，值：%[1]v\n", err) // 原始错误：open not-exist.txt: no such file or directory, 类型：*fs.PathError，值：open not-exist.txt: no such file or directory
  return fmt.Errorf("处理文件失败：%w", err)               // 使用 %w 创建包装错误，会保留原始错误信息（os.ErrNotExist）；如果使用 %v，表示格式化错误，不会保留原始错误信息
 }
 return nil
}

// 多层包装示例
func processData() error {
 if err := readConfig(); err != nil {
  return fmt.Errorf("处理数据失败：%w", err)
 }
 return nil
}

func readConfig() error {
 if err := openFile(); err != nil {
  return fmt.Errorf("读取配置失败：%w", err)
 }
 return nil
}

func openFile() error {
 // 模拟一个具体的错误类型
 return &os.PathError{ // *os.PathError 实现了 error 接口，Error() 方法接收者类型是指针
  Op:   "open",
  Path: "/not/exist/file.txt",
  Err:  os.ErrNotExist,
 }
}
```

#### Join 错误合并

[func Join(errs ...error) error](https://pkg.go.dev/errors#Join) 用于将多个错误合并为一个错误，错误格式为调用每个 errs 元素的 `Error()` 方法的字符串的连接，每个字符串之间用换行符分隔。返回值的底层类型是 `*joinError`。如果有参数为 nil，该参数会被忽略；如果所有参数均为 nil，则返回 nil。

- `errors.Join` 返回的错误实现了 `Unwrap() []error`，`errors.Is` 和 `errors.As` 可以遍历检查其中的每个错误
- `errors.Unwrap(joined)` 返回 nil，因为 `errors.Unwrap` 只识别 `Unwrap() error`，不识别 `Unwrap() []error`

```go
func main() {
 err1 := errors.New("err1")
 err2 := errors.New("err2")
 joined := errors.Join(err1, err2)
 fmt.Printf("类型：%[1]T, 值：%[1]v\n", joined) // 类型：*errors.joinError, 值："err1\nerr2"

 if errors.Is(joined, err2) { // true
  fmt.Println("包含 err2")
 }

 fmt.Println(errors.Unwrap(joined)) // nil，因为 joined 创建的错误没有实现 Unwrap 方法
}
```

### errno

syscall.Errno 是 syscall 包中定义的数值错误类型，该类型也实现了 error 接口。

```go
func main() {
 fmt.Println(syscall.EACCES) // "permission denied"，调用 Error() 方法获取 errno 的字符串描述
 fmt.Println(syscall.ENOENT) // "no such file or directory"
}
```

syscall 包中定义的大多数函数、类型和常量也存在于 [golang.org/x/sys](https://pkg.go.dev/golang.org/x/sys) 包中，新代码应使用 `golang.org/x/sys` 包或 os 包。

```go
import (
 "fmt"
 "os"

 "golang.org/x/sys/unix"
)

func main() {
 fmt.Println(unix.EACCES) // permission denied
 fmt.Println(unix.ENOENT) // no such file or directory

 fmt.Println(os.ErrPermission) // permission denied
 fmt.Println(os.ErrNotExist)   // file does not exist
}
```
