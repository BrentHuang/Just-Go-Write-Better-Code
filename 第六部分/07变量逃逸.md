# 变量逃逸

变量逃逸 (escape) 是在**编译阶段**自动执行的一种内存分配决策机制，指的是本应在栈上分配的局部变量，因为被外部引用而必须在堆上分配的现象，判断的依据是这个变量的生命周期是否可能超出它所在的函数栈帧。

逃逸分析是编译器在编译期判断变量应分配在栈上还是堆上的静态分析，其价值在于把可以安全放在栈上的变量保留在栈上、减少不必要的堆分配。不过并非所有逃逸都应避免：返回大结构体的指针虽然会触发逃逸，却能避免值传递的拷贝开销，需要具体权衡。观察逃逸分析结果的命令如下：

```bash
go build -gcflags="-m" main.go  # -m 打印编译器的优化决策，包括内联和逃逸分析
# 查看更详细的逃逸位置
go build -gcflags="-m -l" main.go  # -l 禁用内联，避免内联掩盖逃逸，便于观察真实的逃逸分析结果
```

## 堆区

堆（heap）是一块动态分配的内存空间，由 Go 运行时的内存分配器与垃圾回收器 GC 管理，用于存储生命周期超出当前函数作用域（逃逸）或无法在编译期确定大小的对象。

- 在大多数系统架构上堆向高地址增长
- 一个程序中的所有协程共享同一个堆

堆中的典型存放对象：

- 显式分配：通过 `new()` 或 `make()` 创建且发生逃逸的对象。`new()` 本身不决定变量是在堆上还是在栈上分配，完全由逃逸分析决定，一个没有逃逸的 `new(T)` 返回的指针可能指向栈。`make()` 用于映射、通道时，其底层结构通常逃逸到堆上，因为 Go 运行时需要跨协程管理它们。`make([]T, ...)` 创建的切片的“引用头”和底层数组的分配位置同样都由逃逸分析决定
- 闭包捕获的外部变量：被闭包引用的外部变量会逃逸到堆上，其生命周期得以延长
- 大型对象：无论是否逃逸，过大的对象会直接在堆上分配，以避免栈溢出。具体阈值是编译器实现细节，不同版本可能不同
- `sync.Pool` 中 `New()` 函数返回的对象：在使用 `sync.Pool` 时，`New()` 函数返回的对象会逃逸到堆上，`sync.Pool` 的目的就是复用这些逃逸到堆上的对象

```go
// 无论是否逃逸，大型对象会直接在堆上分配，以避免栈溢出
func bigArray() {
 var a [1000000]int
 for i := range a {
  a[i] = i
 }
}

func main() {
 bigArray()
}
```

`go build -gcflags="-m -l" main.go` 输出如下：

```text
# command-line-arguments
./main.go:5:6: moved to heap: a
```

用 `new()` 分配的内存也可能不在堆上：

```go
// y 的生命周期完全限定在函数 g() 内部，编译器就选择在栈上分配 y，函数返回时随栈帧一起释放，无需 GC 参与
func g() {
 y := new(int)
 *y = 1
}

func main() {
 g()
}
```

`go build -gcflags="-m -l" main.go` 输出如下：

```text
# command-line-arguments
./main.go:5:10: new(int) does not escape
```

Go 不存在“栈变量”和“堆变量”的语法区分，开发者无法指定变量分配在堆上，只能由编译器决定。

## 变量逃逸常见场景

### 返回局部变量的地址（最常见）

函数返回了局部变量的地址，该指针变量在函数调用结束后仍需使用，其指向的栈变量必须逃逸到堆上。

优化策略：返回值而不是指针。如果返回的结构体较大，返回指针虽然导致逃逸，但避免了值传递的拷贝开销，此时逃逸反而可能提升性能。

```go
func escape() *int {
 v := 100 // 逃逸到堆上
 return &v
}

func main() {
 p := escape()
 fmt.Println(*p)
}

// # command-line-arguments
// ./main.go:8:2: moved to heap: v
// ./main.go:14:13: ... argument does not escape
// ./main.go:14:14: *p escapes to heap
```

### 将局部变量的地址赋值给全局指针

```go
var global *int

func store() {
 x := 15 // 逃逸到堆上
 global = &x
}

func main() {
 store()
 fmt.Println(*global)
}

// # command-line-arguments
// ./main.go:10:2: moved to heap: x
// ./main.go:16:13: ... argument does not escape
// ./main.go:16:14: *global escapes to heap
```

### 被闭包引用

被闭包引用的外部变量，若闭包内部修改该变量，该变量会逃逸到堆上；若闭包只读取该变量，编译器可能按值复制一份副本，此时栈上的原变量并不逃逸。

```go
func closure() func() int {
 x := 10 // 本例闭包只读取 x，编译器可能按值捕获，原变量不一定逃逸
 return func() int { return x }
}

func main() {
 f := closure()
 fmt.Println(f())
}

// # command-line-arguments
// ./main.go:9:9: func literal escapes to heap
// ./main.go:14:13: ... argument does not escape
// ./main.go:14:15: f() escapes to heap
```

### 赋值给接口

当一个值被赋给接口类型时，接口引入了一层间接引用，编译器无法追踪接口“持有”的这个值后续的去向和生命周期，因此倾向于保守地判定逃逸。

```go
type User struct {
 Name string
 Age  int
}

func f() any {
 var i any
 u := User{Name: "alice", Age: 18} // 值类型局部变量，其副本将随接口装箱逃逸
 i = u                             // 将值类型变量 u 赋值给接口，接口的 data 指针指向 u 的副本，Go 会在堆上分配 u 的副本并将 data 指针指向它
 return i
}

func g() any {
 var i any
 u := User{Name: "alice", Age: 18}
 i = &u // 将 u 的地址赋值给接口，接口的 data 指针指向变量 u 本身。如果 i 的生命周期超出了 u 所在的栈帧（例如被返回），那么通过 data 指针访问 u 将是不安全的，必须逃逸到堆上
 return i
}

func main() {
}

// # command-line-arguments
// ./main.go:11:6: u escapes to heap
// ./main.go:17:2: moved to heap: u
```

### 接口参数导致的意外逃逸

fmt、encoding/json 等函数接收 `...any/any` 参数，传入的值会被装进接口。由于编译器无法穿透接口追踪这些值的去向（尤其 fmt 内部还会用反射进一步处理），它们逃逸到堆上。

```go
func printAll() {
 x := 42
 s := "hello"
 fmt.Printf("x=%d, s=%s\n", x, s) // x 和 s 都逃逸到堆上（编译器无法穿透接口追踪去向）
}

func main() {
}

// # command-line-arguments
// ./main.go:8:12: ... argument does not escape
// ./main.go:8:29: 42 escapes to heap
// ./main.go:8:32: "hello" escapes to heap
```

### 发送指针到通道

当把一个指针发送到通道时，由于该指针可能被其它协程通过通道持有，其指向对象的生命周期不再受当前栈帧约束，因此逃逸到堆上。

```go
var c = make(chan *int)

func send() {
 v := 5 // 逃逸到堆上
 c <- &v
}

func main() {
 go send()
 p := <-c
 fmt.Println(*p)

 time.Sleep(3 * time.Second)
}

// # command-line-arguments
// ./main.go:11:2: moved to heap: v
// ./main.go:18:13: ... argument does not escape
// ./main.go:18:14: *p escapes to heap
```

## 如何减少变量逃逸

减少逃逸的核心是让编译器能够证明变量的生命周期不超过函数栈帧，只要编译器无法证明这一点，就会保守地将其分配到堆上。

优先使用泛型（Go 1.18 引入）或具体类型，绕过接口装箱：向 `any` 类型的切片 `[]any` 或 `map[string]any` 中插入基础类型时，会发生接口装箱（Boxing，即把值包装进接口类型的过程）和堆分配，此时可以用泛型或明确的具体类型替代。

```go
func useAny() {
 s := make([]any, 0, 3)
 for i := range 3 {
  s = append(s, i) // i 装箱，逃逸到堆
 }
}

func main() {
 useAny()
 useGeneric(1, 2, 3) // T 被推断为 int，[]int，无装箱
 useConcrete()
}

// 泛型替代 —— 无装箱
func useGeneric[T any](vals ...T) {
 s := make([]T, 0, len(vals))
 s = append(s, vals...)
}

// 具体类型 —— 也无装箱
func useConcrete() {
 s := make([]int, 0, 3)
 for i := range 3 {
  s = append(s, i)
 }
}

// # command-line-arguments
// ./main.go:4:11: make([]any, 0, 3) does not escape
// ./main.go:6:17: i escapes to heap
// ./main.go:6:13: append does not escape
// ./main.go:18:11: make([]go.shape.int, 0, len(vals)) does not escape
// ./main.go:19:12: append does not escape
// ./main.go:24:11: make([]int, 0, 3) does not escape
// ./main.go:26:13: append does not escape
// ./main.go:12:12: ... argument does not escape
```

如果业务逻辑必须返回接口（例如为了统一处理多种类型），且对象频繁创建，可以使用 sync.Pool 来复用那些逃逸到堆上的对象，减少 GC 压力。

```go
type User struct {
 Name string
 Age  int
}

var pool = sync.Pool{
 New: func() any { return new(User) },
}

func GetUser() any {
 u := pool.Get().(*User) // 从池中取，而非新建
 u.Name = "Alice"
 return u // 复用已分配的对象，装箱指针，不产生新的堆分配
}

func PutUser(u any) {
 pool.Put(u.(*User))
}

func main() {
}

// # command-line-arguments
// ./main.go:13:30: new(User) escapes to heap
// ./main.go:22:14: leaking param: u
```

逃逸到堆上的对象由 GC 管理，如果对象生命周期短、分配频率高，会带来 GC 压力；但如果对象生命周期长、分配频率低，逃逸的影响很小。
