# 闭包

闭包（closure）是函数（通常是一个匿名函数）与其创建时捕获的外部变量（也称为“自由变量”）共同构成的组合体。被捕获的外部变量的生命周期得以延长，即使外层函数已经返回，闭包仍能访问和修改这些变量。

| 特性/方面 | 核心要点 |
| -- | -- |
| 本质 | 闭包是一个匿名函数及其捕获的外部变量共同构成的组合体，本质上是函数值 |
| 变量处理 | 闭包捕获的是外部变量本身，而不是变量的一个副本 |
| 关键行为 | 即使外层函数已经执行完毕，其参数、局部变量等只要仍在闭包中使用（被闭包捕获），就不会被回收，生命周期得以延长 |
| 内存分配 | 被闭包捕获的外部变量通常会逃逸到堆上分配内存，以保证在闭包执行时变量依然有效 |
| 非并发安全 | 多个协程并发调用闭包时，可能出现数据竞争，需要同步机制（如互斥锁）保护对被捕获的外部变量的读写 |

计数器是经典的闭包案例：

```go
// newCounter() 是一个返回闭包的工厂函数
func newCounter() func() int {
 i := 0 // i 是被下面的匿名函数捕获的外部变量，捕获的是变量本身，而不是变量的一个副本
 return func() int {
  i++ // 使用被捕获的外部变量
  return i
 }
}

func main() {
 c1 := newCounter()                // c1 是一个闭包，闭包中的变量 i 从 0 开始计数
 fmt.Println(unsafe.Sizeof(c1)) // 8  --闭包本质是函数值，被捕获的外部变量存放在 funcval 的变长数据区中
 fmt.Println(c1())              // 1  --每次调用闭包 c1 时，i 都会加 1
 fmt.Println(c1())              // 2
 fmt.Println(c1())              // 3

 c2 := newCounter()                // 创建一个新的闭包 c2，新闭包中的变量 i 从 0 开始计数
 fmt.Println(unsafe.Sizeof(c2)) // 8
 fmt.Println(c2())              // 1
 fmt.Println(c2())              // 2

 // if c1 == c2 {  // 编译报错，函数之间不能比较，函数只能与 nil 比较
 // }
}
```

在上述示例中，`newCounter()` 函数体中的局部变量 `i` 的生命周期并不随着 `newCounter()` 调用返回而结束，因为它被返回的匿名函数捕获了。

`c1` 与 `c2` 是两个不同的闭包，它们指向的是不同的 `funcval` 结构体。多次调用 `c1()` 操作的是同一个变量 `i`，多次调用 `c2()` 操作的则是另一个变量 `i`。这里的 `funcval` 是 Go 运行时的内部结构体，用于存放函数指针及被闭包捕获的变量。

## 捕获函数局部变量对比包级变量

捕获函数局部变量：

```go
// newAdder() 返回一个闭包，调用 newAdder() 返回的每个闭包都绑定了各自的 sum 变量，初始值都为 0
func newAdder() func(int) int {
 sum := 0
 return func(x int) int {
  sum += x
  return sum
 }
}

func main() {
 pos, neg := newAdder(), newAdder()
 for i := range 3 {
  fmt.Printf("%d, %d\n", pos(i), neg(-2*i)) // 同一个闭包被多次调用时，sum 变量的值会累加；不同闭包的 sum 值互不干扰
 }
}

// 0 0
// 1 -2
// 3 -6
```

捕获包级变量，对比以下代码段与上一代码段的结果：

```go
var sum int = 0 // 包级变量

// newAdder() 返回一个闭包，调用 newAdder() 返回的每个闭包都绑定了同一个包级变量 sum
func newAdder() func(int) int {
 return func(x int) int {
  sum += x
  return sum
 }
}

func main() {
 pos, neg := newAdder(), newAdder()
 for i := range 3 {
  fmt.Printf("%d, %d\n", pos(i), neg(-2*i)) // 不同的闭包被调用时，sum 变量的值会累加，因为 sum 是包级变量，被闭包共享
 }
}

// 0 0
// 1 -1
// 1 -3
```

## 一次返回两个闭包

一次返回两个闭包，这两个闭包共享同一个外部变量：

```go
// newIncrementAndReset() 返回两个闭包：一个递增计数器，一个重置计数器。
// 一次返回的 increment 和 reset 共享同一个 counter 变量
func newIncrementAndReset() (func() int, func() int) {
 counter := 0

 increment := func() int {
  counter++
  return counter
 }

 reset := func() int {
  counter = 0
  return counter
 }

 return increment, reset
}

func main() {
 increment, reset := newIncrementAndReset()

 fmt.Println(increment()) // 1
 fmt.Println(increment()) // 2
 fmt.Println(reset())     // 0
 fmt.Println(increment()) // 1
 fmt.Println(increment()) // 2
}
```

## 闭包非并发安全

多个协程并发调用闭包时，可能出现数据竞争，需要同步机制（如互斥锁）保护对被捕获的外部变量的读写。

```go
func newSafeCounter() func() int {
 var i int
 var mu sync.Mutex // 互斥锁，用于保护对 i 的访问

 return func() int {
  mu.Lock()
  defer mu.Unlock()
  i++ // i++ 并不是原子操作，多个协程并发调用闭包时会出现数据竞争，需要同步机制保护对 i 的读写
  return i
 }
}

func main() {
 c := newSafeCounter()
 var wg sync.WaitGroup

 loopCount := 1000
 for range loopCount {
  wg.Go(func() {
   fmt.Println(c())
  })
 }

 wg.Wait()
 fmt.Println(c()) // 最终输出应为 loopCount+1（即 1001）
}
```

## 闭包捕获循环变量

循环变量 `i` 的变化：

- Go 1.22 之前：循环变量 `i` 在整个循环过程中保持不变
- Go 1.22+：语言规范发生了变化，循环的每次迭代都会创建一个新的循环变量 `i`，每次迭代中的变量 `i` 都有不同的内存地址

这个变化主要是为了解决 Go 开发者长期面临的一个常见陷阱：闭包捕获循环变量 `i` 导致的意外行为。

```go
func main() {
 fmt.Println(runtime.Version())

 funcs := []func() int{} // 元素为 "func() int" 类型的切片
 for i := 0; i < 3; i++ {
  funcs = append(funcs, func() int { return i }) // 闭包捕获循环变量 i。这里会创建一个闭包并赋值给 append 的第二个参数
 }

 for _, f := range funcs {
  fmt.Println(f()) // 在 Go 1.22 之前版本输出：3 3 3，而不是期望的 0 1 2
 }
}
```

其根本原因是闭包捕获的是外部变量 `i` 本身，而不是 `i` 的一个副本。

## 闭包使用场景

### 状态封装

闭包能够“记住”其创建时的上下文环境，这使得它非常适合于封装和隔离状态，外部代码只能通过闭包访问或修改这些状态。如上面的计数器 `newCounter()`，这种方式比使用全局变量更安全，因为它避免了全局命名空间的污染和不可控的修改。

### 工厂函数

`newCounter`、`newAdder` 也属于工厂函数，但它们更侧重状态封装。闭包作为更纯粹的工厂时，可以根据参数动态生成行为不同的函数：

```go
func newMultiplier(factor int) func(int) int {
 return func(x int) int {
  return x * factor
 }
}

func main() {
 double := newMultiplier(2)
 triple := newMultiplier(3)
 fmt.Println(double(5)) // 输出：10
 fmt.Println(triple(5)) // 输出：15
}
```

### 实现装饰器

装饰器模式允许开发者给一个函数添加功能，而无需修改这个函数的代码实现。闭包是实现装饰器的理想工具，例如为函数添加执行时间日志。

```go
// 装饰器函数，记录传入函数的执行时间，无需修改被装饰的函数代码
// 返回闭包可以记住（捕获）被装饰的函数 fn
func logExecutionTime(fn func()) func() {
 return func() {
  start := time.Now()
  fn()
  duration := time.Since(start)
  fmt.Println("Function executed", "duration", duration)
 }
}

// 非装饰器，即时调用，每次调用都要传入 fn，不能记住被装饰的函数
func logExecutionTimeDirect(fn func()) {
 start := time.Now()
 fn()
 duration := time.Since(start)
 fmt.Printf("Function executed, duration: %v\n", duration)
}

func main() {
 myTask := func() {
  fmt.Println("Task started.")
  time.Sleep(time.Duration(rand.IntN(3)) * time.Second)
  fmt.Println("Task finished.")
 }
 loggedTask := logExecutionTime(myTask)
 loggedTask() // 其中记住了被装饰的函数 fn
 loggedTask()

 logExecutionTimeDirect(myTask) // 每次调用都要传入 fn
 logExecutionTimeDirect(myTask)
}
```

问题：`logExecutionTime` 仅适用于 `func()` 签名，不同签名的函数怎么复用？

答案：Go 中很难实现覆盖任意签名的万能装饰器。务实做法是针对需要的函数签名逐个进行包装，或直接在业务逻辑内部计时。

### 回调函数与异步处理

在异步编程或事件驱动模型中，闭包作为回调函数可以简化代码，因为它能够引用函数创建时的外部变量，而无需将这些变量通过参数显式传递。

```go
var wg sync.WaitGroup

// 模拟一个异步任务，执行完成后调用传入的回调函数，这个回调函数用于打印任务执行结果（通用）
func performAsyncTask(callback func(result string, err error)) {
 wg.Go(func() {
  // 模拟一些操作
  err := os.Mkdir("/tmp/testdir", 0755)

  // 操作完成后执行回调
  if err != nil {
   callback("", err)
  } else {
   callback("Task Done!", nil)
  }
 })
}

// 功能同上，但函数参数更多，不够简洁
func performAsyncTask2(taskID string, callback func(taskID string, result string, err error)) {
 wg.Go(func() {
  // 模拟一些操作
  err := os.Mkdir("/tmp/testdir", 0755)

  // 操作完成后执行回调
  if err != nil {
   callback(taskID, "", err)
  } else {
   callback(taskID, "Task Done!", nil)
  }
 })
}

// 普通函数作为回调时，必须要增加 taskID 参数
func callback2(taskID string, result string, err error) {
 if err != nil {
  fmt.Printf("Task %s failed with error: %v\n", taskID, err)
  return
 }
 fmt.Printf("Task %s completed with result: %s\n", taskID, result)
}

func main() {
 taskID := "task-123"
 callback := func(result string, err error) {
  // 闭包捕获了外部的 taskID 变量，可以直接使用，无需为匿名函数增加一个 taskID 参数
  if err != nil {
   fmt.Printf("Task %s failed with error: %v\n", taskID, err)
   return
  }
  fmt.Printf("Task %s completed with result: %s\n", taskID, result)
 }

 performAsyncTask(callback)
 performAsyncTask2(taskID, callback2)

 wg.Wait()
}
```

### 延迟执行与释放资源

结合 defer 语句，闭包常用于确保资源在函数退出时被正确释放。

```go
// 资源清理：闭包捕获 f 和 filename，在 defer 中执行带错误处理的关闭操作
func processFile(filename string) error {
 f, err := os.Open(filename)
 if err != nil {
  return err
 }
 defer func() {
  if err := f.Close(); err != nil { // 闭包捕获了外部变量 f 和 filename
   fmt.Printf("closing file %s failed, err: %v\n", filename, err)
  }
 }()

 // ... 处理文件

 return nil
}
```

## 注意事项

- 内存管理：闭包会延长被其捕获的外部变量的生命周期，如果闭包长期存在（如赋值给全局变量），它引用的外部变量也就不会被回收，可能导致内存泄漏
- 代码可读性：过度或嵌套使用闭包会导致代码逻辑复杂，降低可读性，使用结构体和方法可能更清晰
