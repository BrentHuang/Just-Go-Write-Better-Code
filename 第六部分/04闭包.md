
## closure 闭包

闭包是一个匿名函数及其被创建时所处的词法环境的组合，这个词法环境包含了这个函数所能访问的所有外部变量，也称为“自由变量”。这些变量不仅包括直接外层作用域的变量，还包括所有祖先作用域直到全局作用域的变量。被这个匿名函数引用（捕获）的外部变量在函数创建返回后依然与其绑定，生命周期得以延长。

| 特性/方面 | 核心要点 |
| -- | -- |
| 本质 | 闭包是一个匿名函数及其引用（捕获）的外部变量共同构成的组合体 |
| 关键行为 | 捕获并“记住”外部变量，即使外层函数已经执行完毕，其参数、局部变量只要仍在闭包中使用，就不会被回收，生命周期得以延长 |
| 变量处理 | 闭包捕获的是外部变量本身，而不是变量的一个副本 |
| 内存分配 | 被闭包捕获的外部变量通常会逃逸到堆（heap）上分配内存，以保证在闭包执行时变量依然有效 |
| 非并发安全 | 多个 Goroutine 并发调用闭包操作被捕获的外部变量时，会产生竞态条件，需要同步机制（如互斥锁） |

计数器是经典的闭包案例：

```go
// counter 返回一个闭包计数器
func counter() func() int {
 i := 0  // i 是被下面的匿名函数捕获的外部变量
 return func() int {
  i++  // 修改捕获的变量
  return i
 }
}

func main() {
 c1 := counter()                // c1 是一个闭包，闭包中的变量 i 从 0 开始计数
 fmt.Println(unsafe.Sizeof(c1)) // 8，闭包的 size 也恒为 8，函数值本身并不存储闭包数据
 fmt.Println(c1())              // 1，每次调用闭包时，i 都会加 1
 fmt.Println(c1())              // 2
 fmt.Println(c1())              // 3

 c2 := counter()                // 创建一个新的闭包，新闭包中的变量 i 从 0 开始计数
 fmt.Println(unsafe.Sizeof(c2)) // 8
 fmt.Println(c2())              // 1
 fmt.Println(c2())              // 2

 // if c1 == c2 {  // 编译报错，函数之间不能比较，函数只能与 nil 比较。（闭包也是函数）
 // }
}
```

在上述示例中，counter() 函数体中的局部变量 i 的生命周期并不随着 counter() 调用返回而结束，因为它被返回的匿名函数捕获了。

c1 与 c2 是两个不同的闭包，每次调用 c1() 都是在操作同一个变量 i，调用 c2() 则是在操作另一个变量 i。

```go
// adder 返回一个闭包，每个闭包都绑定了各自的 sum 变量，初始值都为 0
func adder() func(int) int {
 sum := 0
 return func(x int) int {
  sum += x
  return sum
 }
}

func main() {
 pos, neg := adder(), adder()
 for i := range 3 {
  fmt.Printf("%d, %d\n", pos(i), neg(-2*i))  // 同一个闭包被多次调用时，sum 变量的值会累加；不同闭包的 sum 值互不干扰
 }
}

// 输出：
// 0 0
// 1 -2
// 3 -6
```

注意对比下面代码段的结果与上面代码段的结果：

```go
var sum int = 0

// adder 返回一个闭包，每个闭包都绑定了同一个全局变量 sum
func adder() func(int) int {
 return func(x int) int {
  sum += x
  return sum
 }
}

func main() {
 pos, neg := adder(), adder()
 for i := range 3 {
  fmt.Printf("%d, %d\n", pos(i), neg(-2*i))  // 不同的闭包被调用时，sum 变量的值会累加，因为 sum 是全局变量，被闭包共享
 }
}

// 输出：
// 0 0
// 1 -1
// 1 -3
```

一次返回两个闭包，这两个闭包共享同一个外部变量：

```go
// twoClosures 返回两个闭包：一个递增计数器，一个重置计数器。
// 一次返回的 increment 和 reset 共享同一个 counter 变量
func twoClosures() (func() int, func() int) {
 counter := 0

 increment := func() int {
  counter++
  return counter
 }

 reset := func() int {
  counter = 0
  return counter
 }

 return increment, reset
}

func main() {
 increment, reset := twoClosures()

 fmt.Println(increment())  // 1
 fmt.Println(increment())  // 2
 fmt.Println(reset())      // 0
 fmt.Println(increment())  // 1
 fmt.Println(increment())  // 2
}
```

### 闭包非并发安全

当多个 Goroutine 并发调用闭包时，可能产生竞态条件（race condition），需要使用同步机制（如互斥锁）保护对被捕获的外部变量的操作。

```go
func safeCounter() func() int {
 var i int
 var mu sync.Mutex // 互斥锁，用于保护对 i 的访问
 return func() int {
  mu.Lock()
  defer mu.Unlock()
  i++  // i++ 并不是原子操作，多个 Goroutine 并发调用闭包时会产生竞态条件
  return i
 }
}

func main() {
 counter := safeCounter()
 var wg sync.WaitGroup
 loopCount := 1000
 for range loopCount {
  wg.Go(func() {
   fmt.Println(counter())
  })
 }

 wg.Wait()
 fmt.Println(counter())  // 这里输出 loopCount+1 就没问题
}
```

### 闭包捕获循环变量

在循环中打印变量 i 的内存地址：

```go
func main() {
 fmt.Println(runtime.Version()) // go1.26.5

 for i := 0; i < 3; i++ {
  fmt.Printf("%p ", &i) // %p 输出指针 &i 的值，即 i 的内存地址
 }
}

// 输出：0xc000012128 0xc000012150 0xc000012158，会发现每次循环 i 的地址都不一样
```

循环变量 i 的内存地址的变化：

- Go 1.22 之前：循环变量 i 在整个循环执行过程中共享同一个内存地址
- Go 1.22+：语言规范发生了变化，每次循环都会创建一个新的循环变量 i，每次循环中的变量 i 都有不同的内存地址

这个变化主要是为了解决 Go 开发者长期面临的一个常见陷阱：闭包捕获循环变量 i 导致的意外行为。

```go
func main() {
 fmt.Println(runtime.Version())

 funcs := []func() int{} // 元素为 "func() int" 类型的切片
 for i := 0; i < 3; i++ {
  funcs = append(funcs, func() int { return i }) // 闭包捕获循环变量 i。这里会创建一个闭包并赋值给 append 的第二个参数
 }

 for _, f := range funcs {
  fmt.Println(f()) // 在 Go 1.22 之前版本输出：3 3 3，而不是期望的 0 1 2
 }
}
```

其根本原因是闭包捕获的是外部变量 i（外部变量）本身，而不是 i 的一个副本。

### 闭包使用场景

#### 状态封装

闭包能够“记住”其创建时的上下文环境，这使得它非常适合于封装和隔离状态，外部代码只能通过闭包提供的函数来访问或修改这些状态。如上面的计数器 counter，这种方式比使用全局变量更安全，因为它避免了全局命名空间的污染和不可控的修改。

#### 回调函数与异步处理

在异步编程或事件驱动模型中，闭包作为回调函数可以简化代码，因为它能够引用函数创建时的外部变量，而无需将这些变量通过参数显式传递。

```go
var wg sync.WaitGroup

// 模拟一个异步任务，完成后调用传入的回调函数，这个回调函数用于打印任务执行结果（通用）
func performAsyncTask(callback func(result string, err error)) {
 wg.Go(func() {
  // 模拟一些操作
  err := os.Mkdir("/tmp/testdir", 0755)

  // 操作完成后执行回调
  if err != nil {
   callback("", err)
  } else {
   callback("Task Done!", nil)
  }
 })
}

func main() {
 taskID := "task-123"
 performAsyncTask(func(result string, err error) { // 这里会创建一个闭包并赋值给 performAsyncTask 的 callback 参数
  // 闭包捕获并使用了外部的 taskID 变量，而无需通过参数显式传递
  if err != nil {
   fmt.Printf("Task %s failed with error: %v\n", taskID, err)
   return
  }
  fmt.Printf("Task %s completed with result: %s\n", taskID, result)
 })

 wg.Wait()
}
```

#### 工厂函数

闭包可以作为工厂，动态生成具有不同行为或配置的函数。这在需要创建一系列功能相似但某些细节不同的函数时非常有用。

```go
func MakeMultiplier(factor int) func(int) int {
 return func(x int) int {
  return x * factor
 }
}

func main() {
 double := MakeMultiplier(2)
 triple := MakeMultiplier(3)
 fmt.Println(double(5)) // 输出：10
 fmt.Println(triple(5)) // 输出：15
}
```

#### 延迟执行与懒加载

结合 defer 语句，闭包常用于确保资源（如文件句柄、网络连接、锁）在函数退出时被正确释放。此外，闭包也能实现懒加载，只在第一次需要时才执行开销较大的初始化操作。

```go
// 1. 资源清理（闭包捕获 f，在 defer 中执行带错误处理的关闭操作）
func processFile(filename string) error {
 f, err := os.Open(filename)
 if err != nil {
  return err
 }
 defer func() {
  if err := f.Close(); err != nil { // 闭包捕获了外部变量 f
   fmt.Printf("closing file %s failed, err: %v\n", filename, err) // 记录错误日志
  }
 }()

 // ... 处理文件
 return nil
}

// 2. 懒加载，这个示例其实是将 data 变量与闭包绑定在一起
func LazyLoadData() func() string {
 var data string
 return func() string {
  if data == "" {
   // 在并发场景下需要使用 sync.Once 确保初始化只执行一次
   fmt.Println("Expensive data loading...")
   data = "Loaded Data"
  }
  return data
 }
}

func main() {
 loadData := LazyLoadData()

 fmt.Println(loadData())
 // Expensive data loading...
 // Loaded Data

 fmt.Println(loadData()) // Loaded Data
}
```

#### 实现装饰器

装饰器模式允许开发者给一个函数添加功能，而无需修改这个函数的代码实现。闭包是实现装饰器的理想工具，例如为函数添加执行时间日志。

```go
// 装饰器函数，记录传入函数的执行时间，无需修改被装饰的函数代码
// 可以记住被装饰的函数 fn
func LogExecutionTime(fn func()) func() {
 return func() {
  start := time.Now()
  fn()
  duration := time.Since(start)
  fmt.Println("Function executed", "duration", duration)
 }
}

// 非装饰器，即时调用，每次调用都要传入 fn，不能记住被装饰的函数
func LogExecutionTime2(fn func()) {
 start := time.Now()
 fn()
 duration := time.Since(start)
 fmt.Printf("Function executed, duration: %v\n", duration)
}

func main() {
 myTask := func() {
  fmt.Println("Task started.")
  time.Sleep(time.Duration(rand.IntN(3)) * time.Second)
  fmt.Println("Task finished.")
 }
 loggedTask := LogExecutionTime(myTask)
 loggedTask()
 loggedTask()

 LogExecutionTime2(myTask)
 LogExecutionTime2(myTask)
}
```

问题：不同的函数签名不同，怎么做到通用？难道为每个函数都写一个装饰器？答案：Go 社区不追求“万能装饰器”，而是为需要的函数手动写包装或在业务逻辑内部直接计时。

### 注意事项

- 内存管理：闭包会延长被其捕获的外部变量的生命周期，如果闭包长期存在（如赋值给全局变量），它引用的外部变量也就不会被回收，可能导致内存泄漏
- 代码可读性：过度或嵌套使用闭包会导致代码逻辑复杂，降低可读性，使用结构体和方法可能更清晰
