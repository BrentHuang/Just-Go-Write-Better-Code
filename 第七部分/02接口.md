# 接口类型

接口是一种抽象类型，它通过定义行为规范来实现多态和解耦。

用 `interface` 关键字定义接口类型，其中声明了一组方法签名（方法名、参数列表和返回值列表），方法名首字母大小写决定其可见性（是否导出）。

接口名通常以 er 结尾，例如 `Reader`、`Writer`。接口名首字母大小写决定其可见性（是否导出）。

```go
// 接口声明了一组方法签名（行为）
type Abser interface {
 Abs() float64 // 方法签名，前面不加 func 关键字
}
```

任何类型只要实现了接口中声明的所有方法，就隐式满足了该接口，即实现了该接口。类型 `T` 通过定义方法来实现接口，方法接收者参数可以是值类型 `(t T)` 或指针类型 `(t *T)`。

方法接收者参数类型决定了：

- 实现接口的具体类型是 `T` 还是 `*T`（重要）
- 接口可以持有的是 `T` 类型的变量还是 `*T` 类型的变量（可以持有实现了接口的具体类型的变量）

| 方法接收者参数类型 | 实现接口的具体类型 | 接口持有规则 |
| -- | -- | -- |
| 值接收者 | `T` 和 `*T` 都实现了接口 | `T` 类型的变量和 `*T` 类型的变量均可赋值给接口 |
| 指针接收者 | 仅 `*T` 实现了接口 | 仅 `*T` 类型的变量可赋值给接口，因为在方法中可能修改接收者的状态 |

这正是 Go 的方法集（method set）规则：值类型 `T` 的方法集只包含值接收者方法，指针类型 `*T` 的方法集包含值接收者和指针接收者方法，也就是说，`*T` 的方法集是 `T` 的方法集的超集。

判断一个类型是否满足接口 `I`，唯一的依据是：这个类型的方法集是否包含接口 `I` 声明的全部方法签名。接口满足是编译期基于方法集的静态判定，只看方法签名是否存在，跟方法运行时的接收者是谁毫无关系。

```go
type Abser interface {
 Abs() float64
}

type MyFloat float64

// 如果方法接收者是值类型 (T)，那么 T、*T 都实现了接口，可以将 T 类型的值变量或 *T 类型的指针变量赋值给接口
// 如果方法接收者是指针类型 (*T)，那么只有 *T 实现了接口，只能将 *T 类型的指针变量赋值给接口，不能将 T 类型的值变量赋值给接口（编译报错：该类型没有实现接口）
func (f MyFloat) Abs() float64 { // 方法接收者是值类型，MyFloat 和 *MyFloat 都实现了 Abser 接口
 if f < 0 {
  return float64(-f)
 }
 return float64(f)
}

type Vertex struct {
 X, Y float64
}

func (v *Vertex) Abs() float64 { // 方法接收者是指针类型，仅 *Vertex 实现了 Abser 接口，Vertex 没有实现 Abser 接口
 return math.Sqrt(v.X*v.X + v.Y*v.Y)
}

func main() {
 var a Abser // 接口变量 a，可以持有实现了 Abser 接口的具体类型的变量
 f := MyFloat(-math.Sqrt2)
 v := Vertex{3, 4}

 a = f                // a 可以持有 MyFloat 类型的值变量 f
 fmt.Println(a.Abs()) // 1.4142135623730951

 a = &f               // a 也可以持有 *MyFloat 类型的指针变量 &f
 fmt.Println(a.Abs()) // 1.4142135623730951

 a = &v // a 可以持有 *Vertex 类型的指针变量 &v，不能持有 Vertex 类型的值变量 v

 // a = v // 编译报错：Vertex 没有实现 Abser 接口，不能将 Vertex 类型的值变量 v 赋值给接口变量 a

 f.Abs()
 pf := &f
 pf.Abs() // (*pf).Abs()
 v.Abs()  // (&v).Abs()
 pv := &v
 pv.Abs()

 fmt.Println(a.Abs()) // 5
}
```

接口定义与具体实现不仅可以而且经常放在不同包中，这并不影响它们之间的关联。只要类型满足了接口声明的所有方法，Go 编译器就自动认可这种实现关系。（对比：方法接收者类型定义和方法声明必须在同一个包中）

如果一个类型 `T` 或 `*T` 没有实现接口 `I`，将该类型的变量赋值给接口 `I` 类型的变量会导致编译报错。

怎么查看一个类型实现了哪些接口呢？VS Code 中，在类型上右键，“Find All Implementations”可以查看该类型实现了哪些接口。

## 接口底层结构

接口持有的是一个具体类型（type）和该类型的具体值（value），可以把接口变量看作一个元组 `(type, value)`，通过 `%T` 打印接口持有的具体类型、`%v` 打印该类型的具体值。

```go
// 打印接口持有的具体类型和该类型的具体值
func describe(i interface{}) {
 fmt.Printf("(%[1]T, %[1]v)\n", i)
}

type Vertex struct {
 X int
 Y int
}

func main() {
 describe(10)           // (int, 10)
 describe("hello")      // (string, hello)
 describe(true)         // (bool, true)
 describe(Vertex{1, 2}) // (main.Vertex, {1 2})  --持有的具体类型为值类型，持有的具体值为 Vertex{1,2}

 p := &Vertex{3, 4}
 describe(p) // (*main.Vertex, &{3 4})  --持有的具体类型为指针类型，持有的具体值为 &Vertex{3,4}
}
```

接口底层使用 `eface`（空接口）和 `iface`（非空接口）两种数据结构（源代码：`${GOROOT}/src/runtime/runtime2.go`）：

```go
type eface struct {
    _type *_type         // 类型信息
    data  unsafe.Pointer // 实际数据指针
}

type iface struct {
    tab  *itab           // 接口表信息，存储了接口持有的具体类型及该类型所实现的方法列表
    data unsafe.Pointer  // 实际数据指针
}
```

可以认为接口底层结构是两个指针（类型指针和数据指针），所以在 64 位操作系统上，接口变量的 size 恒为 16 字节。

```go
type Abser interface {
 Abs() float64
}

func main() {
 var i interface{}
 var i1 any
 var s fmt.Stringer
 var a Abser

 fmt.Println(unsafe.Sizeof(i))  // 16
 fmt.Println(unsafe.Sizeof(i1)) // 16
 fmt.Println(unsafe.Sizeof(s))  // 16
 fmt.Println(unsafe.Sizeof(a))  // 16
}
```

当接口持有的具体类型为指针类型时，持有的具体值为指针变量，数据指针 `data` 存储这个指针，指向原始变量本身；当接口持有的具体类型为值类型时，持有的具体值为原始变量的一个副本，数据指针 `data` 存储的是这个副本的地址，指向这个副本。

```go
// 模拟接口底层结构的两个指针
type iface struct {
 tab  unsafe.Pointer
 data unsafe.Pointer
}

// 打印接口持有的具体类型和该类型的具体值
func describe(i interface{}) {
 fmt.Printf("(%[1]T, %[1]v)\n", i)
}

func main() {
 // 情况 1：接口持有指针类型
 x := 42
 fmt.Printf("x 的地址：%p\n", &x) // x 的地址：0x386a5cff8128
 var i1 interface{} = &x
 describe(i1)                          // (*int, 0x386a5cff8128)，data 存储的是 &x
 fmt.Printf("%d\n", unsafe.Sizeof(i1)) // 16
 p1 := (*iface)(unsafe.Pointer(&i1)) // 通过 unsafe.Pointer 作为桥梁重新解释 i1 的底层结构这块内存
 fmt.Printf("指针类型：data = %p, *data 指向的值 = %d\n", p1.data, *(*int)(p1.data)) // 指针类型：data = 0x386a5cff8128, *data 指向的值 = 42  --data 指针存储的是原始变量 x 的地址 &x，指向原始变量 x

 // 情况 2：接口持有值类型
 y := 100
 fmt.Printf("y 的地址：%p\n", &y) // y 的地址：0x386a5cff8150
 var i2 interface{} = y
 describe(i2)                          // (int, 100)
 fmt.Printf("%d\n", unsafe.Sizeof(i2)) // 16
 p2 := (*iface)(unsafe.Pointer(&i2))
 fmt.Printf("值类型：data = %p, *data 指向的值 = %d\n", p2.data, *(*int)(p2.data)) // 值类型：data = 0x4d5f20, *data 指向的值 = 100  --data 指针存储的不是原始变量 y 的地址 &y，而是 y 的一个副本的地址
}
```

注意：将具体类型的变量赋值给接口变量可能导致逃逸，关键取决于接口变量的生命周期。若接口变量作为函数返回值，内部数据很可能逃逸到堆上。性能敏感代码中，频繁将临时变量赋值给接口会产生较多 GC 压力。

### 接口方法调用

通过接口变量调用方法，会执行接口持有的具体类型的同名方法：

- 当接口持有的具体类型为指针类型时，分两种情况：

    | 方法接收者参数类型 | 接口持有 `p *T` 时的实际方法接收者 | 是否影响原始变量 |
    | -- | -- | -- |
    | 值接收者 `(t T)` | `*p` 的一个副本 | 不影响 |
    | 指针接收者 `(t *T)` | 指针 `p` 本身 | 影响 |

- 当接口持有的具体类型为值类型时，方法调用的实际接收者是接口持有的具体值的一个副本

    | 方法接收者参数类型 | 接口持有 `t1 T` 时的实际方法接收者 | 是否影响原始变量 |
    | -- | -- | -- |
    | 值接收者 `(t T)` | `t1` 的一个副本 | 不影响 |

接口持有值类型时，指针接收者方法根本不在其方法集内，所以不存在“接口持有 `t1 T` 且方法接收者是指针”的情况。

```go
type I interface {
 Modify()
}

type T1 struct {
 a int
}

func (t T1) Modify() {
 t.a = 100
}

type T2 struct {
 a int
}

func (t *T2) Modify() {
 t.a = 200
}

func main() {
 var i I
 t1 := T1{}
 t2 := T2{}

  i = t1            // 接口持有的具体类型为值类型，方法的接收者为值类型
  i.Modify()        // 方法的接收者是 t1 的副本的副本，在方法体中对接收者形参的修改不影响 t1
  fmt.Println(t1.a) // 0  --没有改变

  i = &t1           // 接口持有的具体类型为指针类型，方法的接收者为值类型
  i.Modify()        // 方法的接收者是 t1 的一个副本，在方法体中对接收者形参的修改不影响 t1
  fmt.Println(t1.a) // 0  --没有改变

  i = &t2           // 接口持有的具体类型为指针类型，方法的接收者为指针类型
  i.Modify()        // 方法的接收者是一个指针，指向 t2，在方法体中对接收者形参的修改会影响 t2
  fmt.Println(t2.a) // 200  --改变了
}
```

## 接口的零值

接口的零值为 `nil`，`nil` 接口值既不持有具体类型也不持有具体值，或者说只有持有的具体类型和具体值都为 `nil` 时，接口值才为 `nil`。

接口可用 `==` 和 `!=` 比较，规则如下：

1. 两个 `nil` 接口相等
2. 两个非 `nil` 接口相等，当且仅当：
   - 它们持有的具体类型相同
   - 它们持有的具体值相等（使用具体类型的 `==` 运算符比较）
3. 如果接口持有的具体类型是不可比较的类型（如切片、映射、函数），尝试比较这样的接口会引发 panic

```go
type I interface {
 M()
}

type T struct {
 S string
}

func (t T) M() {}

type Uncomparable []int

func (u Uncomparable) M() {}

func main() {
 var i1, i2 I
 fmt.Printf("i1 == nil? %t\n", i1 == nil) // true
 fmt.Printf("i1 == i2? %t\n", i1 == i2)   // true

 t1 := T{S: "hello"}
 t2 := T{S: "hello"}
 t3 := T{S: "world"}
 i1 = t1
 i2 = t2
 var i3 I = t3
 fmt.Printf("i1 == i2? %t\n", i1 == i2) // true，类型和值都相同
 fmt.Printf("i1 == i3? %t\n", i1 == i3) // false，值不同

 // 注意：如果具体类型是不可比较的，进行比较会引发 panic
 var u1, u2 I = Uncomparable{1}, Uncomparable{2}
 fmt.Println(u1 == u2) // panic: runtime error: comparing uncomparable type main.Uncomparable
}
```

在 `nil` 接口上调用方法会引发 panic。

当将一个 `nil` 指针赋值给接口时，接口本身并不为 `nil`，因为虽然它持有的具体值是 `nil`，但持有的具体类型不是 `nil`（为指针类型）。这是 Go 最常见的陷阱之一。

```go
var p *int = nil
var i interface{} = p
fmt.Println(i == nil) // false  --接口持有的具体类型是 *int，持有的具体值是 nil
```

```go
type I interface {
 M()
}

func describe(i I) {
 fmt.Printf("(%[1]T, %[1]v)\n", i)
}

type T struct {
 S string
}

func (t *T) M() { // *T 实现了接口 I
 if t == nil { // 如果这里不判断 nil，当接口持有的具体值为 nil 时，通过接口变量调用方法，执行接口持有的具体类型的同名方法时就会 panic
  fmt.Println("t is nil")
  return
 }
 fmt.Println(t.S)
}

type F float64

func (f F) M() {
 fmt.Println(f)
}

func main() {
 var i I       // 接口的零值为 nil
 if i == nil { // 为 true
  fmt.Println("i is nil")
 }
 describe(i) // (<nil>, <nil>)
 // i.M()       // panic，在 nil 接口上调用方法会引发 panic

 var t *T    // t 为指针的零值 nil
 i = t       // i 持有值为 nil 的指针 t，t 为 nil，i 不为 nil
  describe(i) // (*main.T, <nil>)  --i 持有的具体类型为 *T，持有的具体值为 nil

 if t == nil { // 为 true
  fmt.Println("t is nil")
 }

 if i == nil { // 为 false
  fmt.Println("i is nil")
 }

 i.M() // i 持有的具体类型为 *T，持有的具体值为 nil，调用 M 会走到 t == nil 分支

 i = &T{"hello"}
  describe(i) // (*main.T, &{hello})
 i.M()       // i 持有的具体类型为 *T，持有的具体值为 &T{"hello"}，调用 M 会打印 "hello"

 i = F(math.Pi)
  describe(i) // (main.F, 3.141592653589793)
 i.M()
}
```

## 空接口、any 类型

不包含任何方法签名的接口类型 `interface{}` 被称为空接口，空接口可以持有任何类型的变量，所有类型都自动实现了空接口（空接口中没有方法签名，所有类型都不需要额外实现任何方法就已经满足了空接口）。

`any` 是空接口的类型别名：`type any = interface{}`（Go 1.18 引入）

空接口用于处理未知类型/任意类型的值：

- 作为函数参数：`fmt.Print` 可接受类型为 `interface{}` 的任意数量的参数
- 作为映射的值，实现类似“字典”的效果，值可以是任意类型

```go
func main() {
 var i interface{}
 describe(i) // (<nil>, <nil>)

 i = 42
 describe(i) // (int, 42)

 i = "hello"
 describe(i) // (string, hello)
}

func describe(i interface{}) {
 fmt.Printf("(%[1]T, %[1]v)\n", i)
}
```

## 接口类型赋值、传参

接口本身是值类型（底层由 16 字节的类型指针和数据指针组成），赋值、传参时会拷贝整个 16 字节，但 data 字段是指针，拷贝接口变量时，两个变量的 data 指针指向同一块内存。

当接口持有的具体类型是指针、切片、映射、函数、通道这些引用语义变量时，会表现出引用行为。

接口变量可以用作函数的参数或返回值。

```go
// 参数使用 io.Writer 接口类型，任何实现了 Write 方法的具体类型变量都可以作为参数传入
// 返回 int 类型 和 error 接口类型
func WriteHeader(w io.Writer, key, value string) (int, error) {
 return fmt.Fprintf(w, "%s: %s\r\n", key, value)
}

func main() {
 // 调用方可以传入任何实现了 io.Writer 的具体类型变量
 var buf bytes.Buffer
 n, err := WriteHeader(&buf, "Content-Type", "text/html") // 传入 *bytes.Buffer 类型的变量
 if err != nil {
  panic(err)
 }
 fmt.Printf("%d, %s\n", n, buf.String())            // 25, Content-Type: text/html
 n, err = WriteHeader(os.Stdout, "Server", "nginx") // 传入 *os.File 类型的变量
 if err != nil {
  panic(err)
 }
 fmt.Printf("%d\n", n) // 15
}
```

绝大多数场景下，指向接口的指针类型毫无必要，除非函数需要修改接口变量本身，例如 `json.Unmarshal(data, &var)` 需要传递接口变量的地址给第二个 `interface{}` 参数。

```go
func main() {
 // JSON 数据
 data := []byte(`{"name": "Alice", "age": 30}`)

 // 使用 interface{} 接收解析结果
 var result interface{}

 // 这里必须传递 &result，因为 json.Unmarshal 需要修改 result 的值
 // result 是 interface{} 类型，所以 &result 就是 *interface{} 类型
 err := json.Unmarshal(data, &result)
 if err != nil {
  panic(err)
 }

 fmt.Printf("Result type: %T\n", result)  // map[string]interface {}
 fmt.Printf("Result value: %v\n", result) // map[name:Alice age:30]
}
```

## 接口嵌套

在定义接口类型时，可通过嵌套（也是匿名嵌入）其它接口来创建新接口，这体现了组合优于继承的思想：

```go
type Reader interface {
 Read() []byte
}

type Writer interface {
 Write([]byte) int
}

// ReadWriter 接口由 Reader 和 Writer 两个接口组合而成
type ReadWriter interface {
 Reader // 也是匿名嵌入
 Writer
}
```

上述 `Reader`、`Writer` 是本节教学用的自定义接口，方法签名经过简化，与标准库 `io.Reader`（`Read(p []byte) (n int, err error)`）和 `io.Writer`（`Write(p []byte) (n int, err error)`）不同，请勿混淆。

注意：

- 接口应小而专一，1~3 个方法最佳，大接口应拆分为多个小接口（Go 标准库的 io.Reader、io.Writer、fmt.Stringer 都是小接口的典范）
- 不要过早抽象，建议先有至少两个具体实现再提炼接口，避免过度设计（YAGNI 原则）
- 一个类型可通过实现多组方法满足多个接口

### 结构体匿名嵌入与接口满足

当将一个结构体类型匿名嵌入到另一个结构体类型时，外部结构体会自动获得内部结构体的所有方法（方法提升）。如果匿名内嵌结构体已经满足了某个接口，即实现了这个接口的所有方法，那么外部结构体自然也满足了这个接口，可以作为这个接口的实现类型来使用。

匿名嵌入结构体时，被提升的方法进入外层结构体方法集的规则，取决于“嵌入的是值还是指针”以及“方法接收者是值还是指针”：

| 嵌入方式 | `Inner` 的值接收者方法 | `Inner` 的指针接收者方法 |
| -- | -- | -- |
| 值嵌入 `Inner` | 属于 `Inner` 类型的方法集，提升进 `Outer` 和 `*Outer` | 不属于 `Inner` 类型的方法集，只提升进 `*Outer` |
| 指针嵌入 `*Inner` | 属于 `*Inner` 类型的方法集，提升进 `Outer` 和 `*Outer` | 属于 `*Inner` 类型的方法，提升进 `Outer` 和 `*Outer` |

```go
type Inner struct{ n int }

func (i Inner) Get() int   { return i.n } // 值接收者
func (i *Inner) Set(n int) { i.n = n }    // 指针接收者

type OuterV struct{ Inner }  // 值嵌入
type OuterP struct{ *Inner } // 指针嵌入

type Getter interface{ Get() int } // 只要值接收者方法
type Setter interface{ Set(int) }  // 只要指针接收者方法

func main() {
 ov := OuterV{Inner{1}}
 op := OuterP{&Inner{2}}

 // 值嵌入：Get 提升进 OuterV 和 *OuterV
 var g1 Getter = ov
 var g2 Getter = &ov
 fmt.Println(g1.Get(), g2.Get()) // 1 1

 // 值嵌入：Set 只提升进 *OuterV
 var s1 Setter = &ov
 s1.Set(10)
 fmt.Println(ov.n) // 10  --改的是 ov 内嵌的 Inner
 // var s2 Setter = ov      // 编译错误：OuterV 未实现 Setter

 // 指针嵌入：Get 提升进 OuterP 和 *OuterP
 var g3 Getter = op
 var g4 Getter = &op
 fmt.Println(g3.Get(), g4.Get()) // 2 2

 // 指针嵌入：Set 提升进 OuterP 和 *OuterP
 var s3 Setter = op
 s3.Set(20)
 fmt.Println(op.n) // 20
 var s4 Setter = &op
 s4.Set(30)
 fmt.Println(op.n) // 30
}
```

在如下示例中：`celsiusFlag` 内嵌 `Celsius` 类型，`Celsius` 实现了 `String()` 方法，方法接收者为值类型，该方法会被提升进 `celsiusFlag` 类型和 `*celsiusFlag` 类型的方法集。再加上 `*celsiusFlag` 自己实现了 `Set(string) error` 方法，`*celsiusFlag` 类型也就满足了 `flag.Value` 接口。

```go
// flag.Value 接口：自定义命令行参数

// type Value interface {
//  String() string
//  Set(string) error
// }

type Celsius float64    // 摄氏度
type Fahrenheit float64 // 华氏度

func (c Celsius) String() string { // 实现 fmt.Stringer 接口
 return fmt.Sprintf("%gC", c)
}

type celsiusFlag struct {
 Celsius // 嵌入 Celsius，其 String() 方法会被提升到 celsiusFlag；但方法接收者仍是 Celsius（被嵌入的字段），不是 celsiusFlag
}

// 华氏度 to 摄氏度
func FToC(f Fahrenheit) Celsius {
 return Celsius((f - 32.0) * 5.0 / 9.0)
}

func (f *celsiusFlag) Set(s string) error { // 实现 flag.Value 接口
 var unit string
 var value float64
 fmt.Sscanf(s, "%f%s", &value, &unit) // no error check needed
 switch unit {
 case "C", "°C":
  f.Celsius = Celsius(value)
  return nil
 case "F", "°F":
  f.Celsius = FToC(Fahrenheit(value))
  return nil
 }
 return fmt.Errorf("invalid temperature %q", s)
}

func main() {
 f := celsiusFlag{20.0}
 flag.CommandLine.Var(&f, "temp", "the temperature")
 flag.Parse()
 fmt.Println(f)

 var x flag.Value
 x = &f
 fmt.Printf("(%[1]T, %[1]v)\n", x)
}

// go build -o main
//
// ./main -h
// Usage of ./main:
//   -temp value
//         the temperature (default 20C)
//
// ./main -temp 100C
```
