## 接口类型

接口是一种抽象类型，它通过定义行为规范来实现多态和解耦。

接口定义了一组方法签名（方法名、参数列表和返回值列表），但不包含具体的实现。用 interface 关键字定义接口，接口名通常以 er 结尾，例如 Reader、Writer。接口名和方法名首字母大小写决定其可见性（是否导出）。

```go
// 接口定义了一组方法签名（行为）
type Abser interface {
 Abs() float64 // 方法签名，前面不需要加 func 关键字
}
```

任何类型只要实现了接口中声明的所有方法，就隐式满足了该接口（实现了该接口）。类型 `T` 通过定义方法来实现接口，方法接收者参数可以是值类型 `(t T)`或指针类型 `(t *T)`。

方法接收者参数类型决定了：

- 实现接口的具体类型是 `T` 还是 `*T`（重要）
- 接口变量可接受的是 `T` 类型的变量还是 `*T` 类型的变量（赋值）

| 接收者参数类型 | 实现接口的具体类型 | 接口变量赋值规则 |
| -- | -- | -- |
| 值接收者 | `T` 和 `*T` 都实现了接口 | `T` 类型的变量和 `*T` 类型的变量均可赋值给接口变量 |
| 指针接收者 | 仅 `*T` 实现了接口 | 仅 `*T` 类型的变量可赋值给接口变量，因为在方法中可能修改接收者的状态 |

```go
// 接口定义了一组方法签名（行为）
type Abser interface {
 Abs() float64 // 方法签名，前面不需要加 func 关键字
}

type MyFloat float64

// 如果方法接收者是值类型 (T)，那么 T、*T 都实现了接口，可以将 T 类型的值变量或指针变量赋值给接口变量
// 如果方法接收者是指针类型 (*T)，那么只有 *T 实现了接口，只能将 T 类型的指针变量赋值给接口变量，不能将 T 类型的值变量赋值给接口变量（编译报错：该类型没有实现接口）
func (f MyFloat) Abs() float64 { // MyFloat 实现 Abser 接口的 Abs 方法，方法接收者是值类型
 if f < 0 {
  return float64(-f)
 }
 return float64(f)
}

type Vertex struct {
 X, Y float64
}

func (v *Vertex) Abs() float64 { // *Vertex 实现 Abser 接口的 Abs 方法，方法接收者是指针类型
 return math.Sqrt(v.X*v.X + v.Y*v.Y)
}

func main() {
 var a Abser // 接口变量 a
 f := MyFloat(-math.Sqrt2)
 v := Vertex{3, 4}

 a = f                // MyFloat 实现了 Abser 接口，Abs 方法是值接收者，a 可以持有 Myfloat 的值变量 f
 fmt.Println(a.Abs()) // 1.4142135623730951

 a = &f               // a 也可以持有 MyFloat 的指针变量 &f
 fmt.Println(a.Abs()) // 1.4142135623730951

 a = &v // *Vertex 实现了 Abser 接口，Abs 方法是指针接收者，a 可以持有 Vertex 的指针变量 &v，不能持有 Vertex 的值变量 v

 // a = v // 编译报错：Vertex 没有实现 Abser 接口，不能将 Vertex 的值变量 v 赋值给接口变量 a

 f.Abs()
 pf := &f
 pf.Abs()
 v.Abs()
 pv := &v
 pv.Abs()

 fmt.Println(a.Abs()) // 5
}
```

接口定义与具体实现不仅可以而且经常放在不同包中，这并不影响它们之间的关联。只要类型满足了接口要求的所有方法，Go 编译器就自动认可这种实现关系。（对比：方法接收者类型定义和方法声明必须在同一个包中）

如果一个类型 `T` 或 `*T` 没有实现接口 `I`，将该类型的变量赋值给接口 `I` 类型的变量会导致编译报错。

怎么查看一个类型实现了哪些接口呢？VS Code，在类型上右键，“Find All Implementations”可以查看该类型实现了哪些接口

### 接口底层结构

接口变量可以看作一个实现了该接口的具体类型和该类型的具体值的元组 `(type, value)`，即接口变量持有的是具体类型的具体值。通过 `%T` 打印接口变量持有的具体类型、`%v` 打印该类型的具体值。

```go
// 打印接口变量持有的具体类型和具体值
func describe(i interface{}) {
 fmt.Printf("(%[1]T, %[1]v)\n", i)
}

type Vertex struct {
 X int
 Y int
}

func main() {
 describe(10)           // (int, 10)
 describe("hello")      // (string, hello)
 describe(true)         // (bool, true)
 describe(Vertex{1, 2}) // (main.Vertex, {1 2})，具体类型为值类型，具体值为 Vertex{1,2}

 p := &Vertex{3, 4}
 describe(p) // (*main.Vertex, &{3 4})，具体类型为指针类型，具体值为 &Vertex{3,4}
}
```

接口底层使用 eface（空接口）和 iface（非空接口）两种数据结构（源代码：`${GOROOT}/src/runtime/runtime2.go`）：

```go
type eface struct {
    _type *_type         // 类型信息
    data  unsafe.Pointer // 实际数据指针
}

type iface struct {
    tab  *itab           // 接口表信息，存储了接口变量的具体类型及该类型所实现的方法列表
    data unsafe.Pointer  // 实际数据指针
}
```

可以认为接口底层结构是两个指针（类型信息指针和数据指针），所以在 64 位操作系统上，接口变量的 size 恒为 16。

```go
type Abser interface {
 Abs() float64 // 方法签名，前面不需要加 func 关键字
}

func main() {
 var i interface{}  // 空接口
 var i1 any         // any 是 interface{} 的别名
 var s fmt.Stringer // 非空接口
 var a Abser        // 空接口

 fmt.Println(unsafe.Sizeof(i))  // 16
 fmt.Println(unsafe.Sizeof(i1)) // 16
 fmt.Println(unsafe.Sizeof(s))  // 16
 fmt.Println(unsafe.Sizeof(a))  // 16
}
```

接口变量持有的具体类型为指针类型时，具体值为指针变量，数据指针 data 存储具体值本身；接口变量持有的具体类型为值类型时，具体值为值变量的一个副本，数据指针 data 存储这个副本的地址。

```go
// 模拟接口底层结构的两个指针
type iface struct {
 tab  unsafe.Pointer
 data unsafe.Pointer
}

// 打印接口变量持有的具体类型和具体值
func describe(i interface{}) {
 fmt.Printf("(%[1]T, %[1]v)\n", i)
}

func main() {
 // 情况 1：接口持有指针类型
 x := 42
 fmt.Printf("x 的地址：%p\n", &x) // x 的地址：0x386a5cff8128
 var i1 interface{} = &x
 describe(i1)                          // (*int, 0x386a5cff8128)，data 存储的是 &x
 fmt.Printf("%d\n", unsafe.Sizeof(i1)) // 16
 p1 := (*iface)(unsafe.Pointer(&i1)) // 可以认为 unsafe.Pointer 就是 void*
 fmt.Printf("指针类型：data = %p, *data 指向的值 = %d\n", p1.data, *(*int)(p1.data)) // 指针类型：data = 0x386a5cff8128, *data 指向的值 = 42，data 存储的是 &x

 // 情况 2：接口持有值类型
 y := 100
 fmt.Printf("y 的地址：%p\n", &y) // y 的地址：0x386a5cff8150
 var i2 interface{} = y
 describe(i2)                          // (int, 100)
 fmt.Printf("%d\n", unsafe.Sizeof(i2)) // 16
 p2 := (*iface)(unsafe.Pointer(&i2))
 fmt.Printf("值类型：data = %p, *data 指向的值 = %d\n", p2.data, *(*int)(p2.data)) // 值类型：data = 0x4d5f20, *data 指向的值 = 100，data 存储的不是 &y，而是 y 的一个副本的地址
}
```

将具体类型的变量赋值给接口变量可能导致堆逃逸，关键取决于接口变量的生命周期。若接口变量作为函数返回值，内部数据很可能逃逸到堆上。性能敏感代码中，频繁将临时变量赋值给接口会产生较多 GC 压力。

通过接口变量调用方法，会执行接口持有的具体类型的同名方法：

- 当接口持有值类型时，方法调用的接收者是接口持有的具体值（本身也是原始值的一个副本）的一个副本
- 当接口持有指针类型时，需要区分两种情况：

| 方法接收者参数类型 | 接口持有`*T`时的实际接收者 | 是否影响原始值 |
| -- | -- | -- |
| 值接收者`(t T)` | `*ptr` 的一个副本（解引用后拷贝） | 不影响 |
| 指针接收者`(t *T)` | 指针 `ptr` 本身 | 影响 |

### 接口的零值

接口的零值为 nil。nil 接口值既不持有具体类型也不持有具体值。只有持有的具体类型和具体值都为 nil 时，接口变量才为 nil。在 nil 接口上调用方法会引发 panic。

接口可用 `==` 和 `!=` 比较，规则如下：

1. 两个 nil 接口相等
2. 两个非 nil 接口相等，当且仅当：
   - 它们的具体类型相同
   - 它们的具体值相等（使用具体类型的 `==` 运算符比较）
3. 如果接口的具体类型是不可比较的类型（如切片、map、函数），尝试比较这样的接口会引发 panic

```go
type I interface {
 M()
}

type T struct {
 S string
}

func (t T) M() {}

type Uncomparable []int

func (u Uncomparable) M() {}

func main() {
 var i1, i2 I
 fmt.Printf("i1 == nil? %t\n", i1 == nil) // true
 fmt.Printf("i1 == i2? %t\n", i1 == i2)   // true

 t1 := T{S: "hello"}
 t2 := T{S: "hello"}
 t3 := T{S: "world"}
 i1 = t1
 i2 = t2
 var i3 I = t3
 fmt.Printf("i1 == i2? %t\n", i1 == i2) // true，类型和值都相同
 fmt.Printf("i1 == i3? %t\n", i1 == i3) // false，值不同

 // 注意：如果具体类型是不可比较的，比较会 panic
 var u1, u2 I = Uncomparable{1}, Uncomparable{2}
 fmt.Println(u1 == u2) // panic: runtime error: comparing uncomparable type main.Uncomparable
}
```

常见陷阱：当将一个 nil 指针赋值给接口变量时，接口变量本身不为 nil，因为虽然它的具体值是 nil，但具体类型不是 nil。这是 Go 中最常见的陷阱之一：

```go
var p *int = nil
var i interface{} = p
fmt.Println(i == nil) // false！接口持有 *int 类型和 nil 值
```

```go
type I interface {
 M()
}

// 打印接口变量持有的具体类型和具体值
func describe(i I) {
 fmt.Printf("(%[1]T, %[1]v)\n", i)
}

type T struct {
 S string
}

func (t *T) M() { // *T 实现了接口 I
 if t == nil { // 如果这里不判断 nil，当接口持有的具体值为 nil 时，就会 panic
  fmt.Println("t is nil")
  return
 }
 fmt.Println(t.S)
}

type F float64

func (f F) M() {
 fmt.Println(f)
}

func main() {
 var i I       // 接口的零值为 nil
 if i == nil { // 为 true
  fmt.Println("i is nil")
 }
 describe(i) // (<nil>, <nil>)
 // i.M()       // panic，在 nil 接口上调用方法会引发 panic

 var t *T    // t 为指针的零值 nil
 i = t       // i 被赋值为指针 t，t 为 nil，i 不为 nil，这很特别！
 describe(i) // (*main.T，<nil>)，i 的具体值为 nil

 if t == nil { // 为 true
  fmt.Println("t is nil")
 }

 if i == nil { // 为 false
  fmt.Println("i is nil")
 }

 i.M() // i 的具体类型为 *T，其具体值为 nil，调用 M 会走到 t == nil 分支，打印 "t is <nil>"

 i = &T{"hello"}
 describe(i) // (*main.T，&{hello})
 i.M()       // i 的具体类型为 *T，其具体值为 &T{"hello"}，调用 M 会打印 "hello"

 i = F(math.Pi)
 describe(i) // (main.F，3.141592653589793)
 i.M()
}
```

### 空接口，any 类型

不包含任何方法签名的接口类型被称为空接口，其定义为：`interface{}`，空接口的变量可以持有任何类型的变量，所有类型都自动实现了空接口（空接口中没有方法签名，所有类型都不需要额外实现任何方法就已经满足了空接口）。

any 是空接口的类型别名：`type any = interface{}`

空接口用于处理未知类型/任意类型的值：

- 作为函数参数：fmt.Print 可接受类型为 `interface{}` 的任意数量的参数
- 作为 map 的值，实现类似“字典”的效果，值可以是任意类型

```go
func main() {
 var i interface{}
 describe(i) // (<nil>, <nil>)

 i = 42
 describe(i) // (int, 42)

 i = "hello"
 describe(i) // (string, hello)
}

func describe(i interface{}) {
 fmt.Printf("(%[1]T, %[1]v)\n", i)
}
```

### 接口赋值、传参

接口本身是值类型（底层由 16 字节的类型信息和数据指针组成），赋值、传参时会拷贝整个 16 字节，但 data 字段是指针，拷贝接口变量时，两个变量的 data 指向同一块内存。当接口持有的具体类型是指针、切片、map 等引用语义对象时，会表现出引用行为。

接口变量可以用作函数的参数或返回值。

```go
// 参数使用 io.Writer 接口类型，任何实现了 Write 方法的具体类型变量都可以作为参数传入
// 返回 int 类型 和 error 接口类型
func WriteHeader(w io.Writer, key, value string) (int, error) {
 return fmt.Fprintf(w, "%s: %s\r\n", key, value)
}

func main() {
 // 调用方可以传入任何实现了 io.Writer 的具体类型变量
 var buf bytes.Buffer
 n, err := WriteHeader(&buf, "Content-Type", "text/html") // 传入 *bytes.Buffer
 if err != nil {
  panic(err)
 }
 fmt.Printf("%d, %s\n", n, buf.String())            // 25, Content-Type: text/html
 n, err = WriteHeader(os.Stdout, "Server", "nginx") // 传入 *os.File
 if err != nil {
  panic(err)
 }
 fmt.Printf("%d\n", n) // 15
}
```

接口变量本身包含一个指向实际数据的指针（data 字段），传参时拷贝的 16 字节（类型信息 + data）已经能共享底层数据。所以绝大多数场景下，指向接口的指针类型 `*interface{}` 毫无必要。

但有少数例外场景，例如 `json.Unmarshal(data, &var)` 需要传递变量的地址给第二个 `interface{}` 参数，或者函数需要修改接口变量本身持有的具体类型或具体值时。

```go
func main() {
 // JSON 数据
 data := []byte(`{"name": "Alice", "age": 30}`)

 // 使用 interface{} 接收解析结果
 var result interface{}

 // 这里必须传递 &result，因为 json.Unmarshal 需要修改 result 的值
 // result 是 interface{} 类型，所以 &result 就是 *interface{} 类型
 err := json.Unmarshal(data, &result)
 if err != nil {
  panic(err)
 }

 fmt.Printf("Result type: %T\n", result)  // map[string]interface {}
 fmt.Printf("Result value: %v\n", result) // map[name:Alice age:30]
}
```

### 接口嵌套

接口可通过嵌套其它接口来创建新接口，这体现了组合优于继承的思想：

```go
type Reader interface {
 Read() []byte
}

type Writer interface {
 Write([]byte) int
}

// ReadWriter 接口由 Reader 和 Writer 组合而成
type ReadWriter interface {
 Reader
 Writer
}
```

注意：

- 接口应小而专一，1~3 个方法最佳，大接口应拆分为多个小接口
- 不要过早抽象，建议先有至少两个具体实现再提炼接口，避免过度设计（YAGNI 原则）
- 一个类型可通过实现多组方法满足多个接口

当将一个结构体类型匿名嵌入到另一个结构体类型时，外部结构体会自动“继承”内部结构体的所有方法（方法提升）。如果匿名内嵌结构体已经满足了某个接口，即实现了这个接口的所有方法，那么外部结构体自然也满足了这个接口，可以作为这个接口的实现类型来使用。

示例：celsiusFlag 内嵌 Celsius 类型，假设 Celsius 已实现 String() 方法，该方法自动成为 celsiusFlag 的一部分。再加上 celsiusFlag 自定义实现了 Set(string) error 方法，*celsiusFlag 自然满足 flag.Value 接口。

```go
// flag.Value 接口：自定义命令行参数

// type Value interface {
//  String() string
//  Set(string) error
// }

type Celsius float64    // 摄氏度
type Fahrenheit float64 // 华氏度

func (c Celsius) String() string { // 实现 fmt.Stringer 接口
 return fmt.Sprintf("%gC", c)
}

type celsiusFlag struct {
 Celsius // Celsius 类型实现的 fmt.Stringer 接口方法会提升到 celsiusFlag 类型上
}

// 华氏度 to 摄氏度
func FToC(f Fahrenheit) Celsius {
 return Celsius((f - 32.0) * 5.0 / 9.0)
}

func (f *celsiusFlag) Set(s string) error { // 实现 flag.Value 接口
 var unit string
 var value float64
 fmt.Sscanf(s, "%f%s", &value, &unit) // no error check needed
 switch unit {
 case "C", "°C":
  f.Celsius = Celsius(value)
  return nil
 case "F", "°F":
  f.Celsius = FToC(Fahrenheit(value))
  return nil
 }
 return fmt.Errorf("invalid temperature %q", s)
}

func main() {
 f := celsiusFlag{20.0}
 flag.CommandLine.Var(&f, "temp", "the temperature")
 flag.Parse()
 fmt.Println(f)
}

// go build -o main
//
// ./main -h
// Usage of ./main:
//   -temp value
//         the temperature (default 20C)
//
// ./main -temp 100C
```
