# 包（package）

一个目录下的所有源文件（不包括以 `_test.go` 结尾的测试源文件，也不包括子目录中的源文件）被视为一个整体，共同构成一个包。包是 Go 最基本的代码组织与复用单元，也是编译的最小单元。Go 编译器以包为单位编译，同包中的所有源文件一起被编译为一个目标文件。导入也必须以包为单位，不能只导入某个源文件中的函数或类型。

## 核心概念

- 每个源代码目录对应一个包，目录结构反映包的路径组织。包之间没有父子层级关系，例如 [encoding/json](https://pkg.go.dev/encoding/json) 和 [encoding](https://pkg.go.dev/encoding) 是两个独立的包，前者并非后者的子包。按约定包名与目录名保持一致，但该约定并不被 Go 工具链强制约束
- 每个源文件必须通过 `package` 关键字声明自己所属的包，编译器不会根据源文件所在的目录自动推断。`package` 声明不加双引号，只需写最后一级目录名，示例：`package repository`
- 作为应用程序运行的源文件必须位于 `main` 包中，但其所在目录名通常不叫 main（如 `cmd/myapp/`）
- 一个目录下的所有非测试源文件必须属于同一个包。测试源文件（`_test.go`）可声明为 `package foo`（白盒测试，能访问未导出标识符）或 `package foo_test`（黑盒测试，仅能访问导出标识符），两种测试包可共存于同一目录

示例：

```text
hello-world/
├── foo
│   ├── foo1_test.go
│   ├── foo.go
│   └── foo_test.go
├── go.mod
└── main.go
```

```go
// foo.go
package foo

func Add(a, b int) int {
 return a + b
}

// foo_test.go
package foo

import "testing"

func TestAdd(t *testing.T) {
 if Add(1, 2) != 3 {
  t.Errorf("Add(1, 2) = %d; want 3", Add(1, 2))
 }
}

// foo1_test.go
package foo_test

import (
 "testing"

 "example.com/hello-world/foo"
)

func TestFoo(t *testing.T) {
 if foo.Add(1, 2) != 3 {
  t.Errorf("Add(1, 2) = %d; want 3", foo.Add(1, 2))
 }
}
```

## 包的初始化

每个包在被使用（被某个程序或其它包导入）时都会执行一次初始化，整个过程由 Go 编译器自动完成，无需也不能由用户显式调用：

- 包级变量按依赖顺序初始化：先初始化为零值，再按变量间的依赖关系依次求值
- 在初始化当前包之前，会先完成它所导入的包的初始化；最终呈现为按依赖关系从叶子到根的顺序（与包的层级划分无关）
- 变量初始化完成后，自动调用该包所有的 `init()` 函数；同一包内多个 `init()` 按所在源文件名的顺序执行，无法接受参数、也无法返回结果
- 每个包每次程序运行只初始化一次

`init()` 函数是包级特殊函数，常用于注册驱动、初始化只读配置等无返回值、无参数的初始化任务。

## 包的命名

包名（`package` 声明中指定的名称）通常与目录名一致，应简短、含义明确。命名规则如下：

- 使用全小写单词，单词之间不使用下划线或中划线分隔，所有单词连写在一起
- 使用简洁的单数名词，不使用复数
- 不使用特殊字符

示例：

- 直接连接：`strconv`（string conversion）
- 合理缩写：`fmt`（format）
- 避免使用下划线或中划线（反面示例）：`string_conv`
- 测试包名使用 `_test` 作为后缀：`package foo_test`

例外情况：

- 标准库的 [bytes](https://pkg.go.dev/bytes)、[errors](https://pkg.go.dev/errors) 和 [strings](https://pkg.go.dev/strings) 包名使用复数是为了避免和预定义类型冲突
- 标准库的 [go/types](https://pkg.go.dev/go/types) 包名使用复数是为了避免和 `type` 关键字冲突

## 导出规则

包中大写字母开头的标识符是导出的，小写字母开头的是未导出的。导入一个包后，只能访问该包导出的标识符。

API 最小暴露原则：仅导出外部需要的类型、函数等标识符，内部实现全部以小写字母开头。

注意：无法导入 `main` 包，故 `main` 包不应导出任何标识符。

### 标识符命名规范

Go 标识符必须以 Unicode 字母或下划线开头，后面可以跟任意数量的字母、数字、下划线。不能以数字开头，一般也不以下划线开头。

Go 标识符使用驼峰命名（CamelCase），不使用蛇形命名（snake_case、SNAKE_CASE），也不使用匈牙利命名（strName）。

首字母的大小写决定可见性（是否导出）：

| 命名类型 | 格式 | 使用场景 | 示例 |
| -- | -- | -- | -- |
| 大驼峰 | `CamelCase` | 导出的标识符，能够在包外访问 | `HTTPServer`, `UserID` |
| 小驼峰 | `camelCase` | 未导出的标识符，只能在包内访问 | `localVariable`, `internalFunc` |

注意：

- 单独的下划线 `_` 是一个特殊的空白标识符，与以下划线开头的变量名是完全不同的概念
- 在一个包中任意源文件中定义的包级（非函数体中）标识符（变量、常量、函数、类型、接口），对该包中的其它源文件都是可见的，可以直接访问，如同它们定义在同一源文件中一样

特殊命名场景：

- 缩略词保持全大写，如 `ID`、`HTTP`；私有（未导出）且在开头时全小写，如 `httpHandler`
- 自定义错误类型以 `Error` 结尾，如 `ValidationError`，导出的错误变量以 `Err` 开头，如 `ErrNotFound`，未导出的错误变量以 `err` 开头
- 配置结构体类型以 `Config` 结尾，变量一般为 `cfg` 或 `conf`
- Getter 不加 `Get` 前缀，如 `Owner()` 而非 `GetOwner()`；Setter 加 `Set` 前缀，如 `SetOwner()`
- 测试函数名以 `Test` 开头，可通过下划线对名称分组，如 `TestMyFunction_WhatIsBeingTested`

## 导入方式

在包外必须先导入（import）该包，才能通过包名前缀访问该包导出的标识符。包名前缀本质上是一种命名空间机制，不同包中可以定义同名的标识符，通过包名前缀加以区分，避免命名冲突。示例：

- `fmt.Println` 引用 fmt 包中的 Println 函数
- `math.Pi` 引用 math 包中的 Pi 常量
- `image.Decode` 引用 image 包中的 Decode 函数
- `utf16.Decode` 引用 unicode/utf16 包中的 Decode 函数

导入包的语法：`import "package-path"`

导入路径（包路径，package-path）由“模块路径”加上“该包在模块中的子目录路径”组成。包名通常与导入路径中代表目录名的最后一个元素一致；当最后一段是模块的版本后缀（如 `/v4`）时，包名取其前面的部分。示例：`import "rsc.io/quote/v4"` 导入的包名为 `quote`，通过 `quote.` 访问该包中导出的标识符。

四种导入方式：

| 导入方式 | 语法 | 示例 |
| -- | -- | -- |
| 标准导入 | `import "package-path"` | `import "fmt"`，通过 `fmt.Println()` 访问 |
| 别名导入 | `import alias "package-path"` | `import f "fmt"`，通过 `f.Println()` 访问，适用于包名冲突或简化长包名的场景 |
| 空白导入 | `import _ "package-path"` | `import _ "github.com/lib/pq"`，仅触发被导入包的初始化（自动执行其中的 `init()` 函数），不直接引用该包导出的标识符 |
| 点导入/省略导入 | `import . "package-path"` | `import . "fmt"`，可直接使用 `Println()` 而无需包名前缀。会污染当前命名空间，不建议使用 |

空白导入常见场景：

- 数据库驱动注册：`import _ "github.com/go-sql-driver/mysql"`
- 性能分析工具集成：`import _ "net/http/pprof"`，自动注册 pprof 的 HTTP 处理器
- 容器环境自动配置：`import _ "go.uber.org/automaxprocs"`，根据容器 CPU 配额自动设置 GOMAXPROCS

## 分组导入

使用小括号将导入的包分组，每个包路径占一行：

```go
import (
 "fmt"
 "time"
)
```

分组顺序约定：按“标准库”、“第三方库”、“本项目内部包”的顺序分组，组之间用空行分隔。

```go
import (
 "fmt"
 "net/http"

 "github.com/gin-gonic/gin"

 "myproject/pkg/util"
)
```

## 包注释

- 放在包中任一源文件的 `package` 声明之前，与 `package` 声明之间不能有空行
- 多个源文件的 `package` 声明前都有包注释时，`go doc .` 会按源文件名的顺序将它们合并为一份包文档。包注释很大时通常放到独立的 `doc.go` 文件中（该文件仅含包注释与 `package` 声明）
- 第一句以 `Package <包名>` 开头并以句号结尾，作为包的摘要，后续内容详细说明功能、用途及注意事项
- 可包含使用示例和链接到其它相关文档（链接用中括号）

示例：

```go
// Package mypackage provides awesome functionality.
// More detailed description here...
package mypackage
```

## import 格式化工具

- [goimports](https://pkg.go.dev/golang.org/x/tools/cmd/goimports) 自动添加缺失的 import 并移除未引用的 import。安装：`go install golang.org/x/tools/cmd/goimports@latest`，使用：`goimports -w .`
- [gci](https://github.com/daixiang0/gci) 控制导入顺序并使其始终具有确定性，比 goimports 支持更多自定义选项。安装：`go install github.com/daixiang0/gci@latest`，使用：`gci write --custom-order --section standard --section default --section "prefix(github.com/yourname/your-proj)" .`，prefix 中的 `github.com/yourname/your-proj` 是某项目的模块路径（即 `go.mod` 中 `module` 声明的值）

## 循环导入问题

Go 不允许循环导入（如 A 导入 B，B 又导入 A），会导致编译报错。解决方法：

- 提取公共代码到新包：将 A 和 B 共同依赖的代码提取到独立的包 C，打破循环
- 使用接口解耦：在依赖方定义接口，被依赖方实现接口，避免直接依赖具体类型
- 依赖注入：将依赖通过参数或构造函数传入，而不是在包内部直接创建
- 重新设计包结构：审视包的职责划分，合并职责相近的包或拆分职责过重的包

## internal 包

`internal` 是一个特殊的目录名，位于其下的包称为内部包，只能被该 `internal` 目录的父目录的子树中的代码导入。

示例：

```text
proj/
├── a
│   ├── internal
│   │   ├── x
│   │   └── y
│   └── p
└── b
    └── q
```

可导入 `a/internal/x` 的包：

```text
# ** 表示 0 级或多级目录
a/**/*
a/internal/**/*
```

具体有：

```text
a/p          // 与 internal 同属 a/ 子树
a/internal/y // internal 包下的 y 包
```

不可导入 `a/internal/x` 的包：

```text
b/q          // 不属于 a/ 子树
```

Go 支持嵌套的 `internal` 目录，每个 `internal` 目录的可见范围独立计算。

## 私有仓库

当项目依赖企业内部未公开到互联网的公共库，或需要拉取商业代码时，这些依赖通常托管在私有仓库中。访问私有仓库需完成以下配置：

- 设置私有仓库域名：`go env -w GOPRIVATE=gitlab.com/yourcompany,github.com/yourname`。`GOPRIVATE` 以逗号分隔的路径前缀列表指定 private 模块，Go 工具链会绕过模块代理和校验和数据库，对这类模块使用直连方式拉取并校验
- 确保已有 SSH 密钥对，并且公钥已添加到私有仓库平台：通过 `ssh-keygen -t ed25519 -C "your_email@example.com"` 生成密钥对，将 `~/.ssh/id_ed25519.pub` 的内容添加到代码托管平台的 SSH 公钥设置中

配置完成后，即可在 `go.mod` 中正常引入私有仓库模块，并可用 `go get`、`go mod tidy` 等命令拉取其依赖。

## 包的设计原则

包的作用是对代码进行分类和隔离。好的包不仅命名得当，更在于内部结构清晰合理，应遵循职责单一、避免大包、分层清晰、禁止循环导入等原则。

- 按逻辑拆分文件：一个包可由多个源文件组成，按功能逻辑拆分以提高可读性，例如 `http` 包可拆分为 `headers.go`、`cookies.go`、`http.go` 等
- 按职责组织而非按数据模型：将类型定义在使用处附近，不要创建 `models` 或 `types` 包集中存放数据结构，应将类型放在提供相关服务的包中

参考：[标准 Go 项目结构](https://github.com/golang-standards/project-layout)。
