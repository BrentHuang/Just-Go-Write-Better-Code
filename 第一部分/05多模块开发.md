# 多模块开发

一个模块包含其 `go.mod` 文件所在目录下的所有包，以及该目录下的所有子目录中的包，直到遇到下一个包含 `go.mod` 文件的子目录为止。

大多数项目只包含一个模块（`go.mod` 文件位于项目根目录），但 Go 也支持在一个项目中包含多个模块。多模块开发有两种方案：

1. 通过 `go mod edit -replace` 将模块路径替换为本地路径
2. 多模块工作区：将多个模块添加到一个工作区中

## replace 指令

参考教程：[创建模块](https://go.dev/doc/tutorial/create-module)，[调用模块](https://go.dev/doc/tutorial/call-module-code)

call-module 示例项目结构：

```text
call-module/
├── greetings/          # go mod init example.com/greetings，第一个模块（库），模块路径为 example.com/greetings
│   ├── greetings.go
│   ├── greetings_test.go
│   └── go.mod
└── hello/              # go mod init example.com/hello，第二个模块（应用程序），模块路径为 example.com/hello
    ├── main.go
    └── go.mod
```

```go
// greetings/greetings.go
package greetings

import "fmt"

// Hello returns a greeting for the named person.
func Hello(name string) string {
 message := fmt.Sprintf("Hi, %v. Welcome!", name)
 return message
}
```

```go
// greetings/greetings_test.go
package greetings

import (
 "fmt"
 "testing"
)

func TestHelloName(t *testing.T) {
 name := "Gladys"
 want := fmt.Sprintf("Hi, %v. Welcome!", name)
 msg := Hello(name)
 if msg != want {
  t.Errorf(`Hello(%q) = %q, want match for %#q`, name, msg, want)
 }
}
```

```go
// hello/main.go
package main

import (
 "fmt"

 "example.com/greetings" // 导入 greetings 包，导入路径为模块路径（example.com/greetings）+ 包在模块中的子目录路径（为空）
)

func main() {
 message := greetings.Hello("Gladys")
 fmt.Println(message)
}
```

模块 `example.com/greetings` 尚未发布到公网时，需要将模块路径替换为本地路径才能访问：

在 `hello` 目录执行：

```bash
go mod edit -replace example.com/greetings=../greetings
```

该命令会在 `hello/go.mod` 中增加一条 `replace` 指令：`replace example.com/greetings => ../greetings`。

常用操作：

- 在 `greetings` 目录执行 `go test` 运行测试用例
- 在 `hello` 目录执行 `go run .` 或 `go run main.go` 编译并运行应用程序
- 在 `hello` 目录执行 `go build` 编译应用程序

## 多模块工作区

`go work` 是 Go 1.18 引入的工作区模式，用于同时开发多个相互依赖的模块。语法：`go work [init|sync|edit|use|vendor] [arguments]`。

go 命令从当前目录逐级向上查找 `go.work` 文件，找到即启用工作区模式；`go env GOWORK` 可查看当前生效的工作区文件路径，把 `GOWORK` 设为 `off` 可关闭工作区模式。

工作区文件 `go.work` 通过 `use` 指令列出一组本地模块，它们共同作为主模块（main modules）参与依赖解析；在源文件中 `import` 工作区内的模块时，`go build|run|test` 会使用该模块的本地代码，而非 `go.mod` 中 `require` 的版本。

`go.work` 文件示例：

```text
go 1.24.1

use (
 ./app
 ./lib
 ./pkg
)
```

常用命令：

- `go work init [moddirs]`：生成 `go.work` 文件并初始化工作区，一般在项目根目录执行
- `go work use [-r] [moddirs]`：将本地模块添加到工作区，例如 `go work use ./app ./lib`，`-r` 表示递归添加模块，多个模块目录之间用空格分隔
- `go work sync`：将工作区中解析的依赖版本同步到各模块的 `go.mod` 文件
- `go work vendor`（Go 1.22+）：将工作区中所有模块的依赖复制到 `vendor` 目录，用于离线构建。与 `go mod vendor` 类似，但作用于整个工作区
- `go work edit`：以命令行方式编辑 `go.work` 文件

除各模块自身的 `go.sum` 外，工作区构建还可能生成 `go.work.sum` 文件，用于记录工作区构建所需的、不属于任一 `go.sum` 的依赖模块校验和。

通常不建议将 `go.work` 和 `go.work.sum` 提交到版本控制系统，因为其中的模块路径和版本是针对某台开发机设置的，提交后所有检出者都会被强制使用同一份工作区配置，也可能导致 CI 解析出与各模块 `go.mod` 不一致的依赖版本。仅在团队约定统一使用工作区（如 monorepo 单一仓库，指的是把多个项目、模块或服务放在同一个代码仓库里管理，而不是每个项目单独一个仓库）的场景下，才考虑提交。

### 示例项目

参考教程：[工作区](https://go.dev/doc/tutorial/workspaces)

项目结构：

```text
workspace/
└── hello/              # go mod init example.com/hello
    ├── main.go
    └── go.mod
```

```go
// hello/main.go
package main

import (
 "fmt"

 "golang.org/x/example/hello/reverse" // 导入 golang.org/x/example/hello 模块中的 reverse 包
)

func main() {
 fmt.Println(reverse.String("Hello"))
}
```

在 `workspace` 目录执行 `go work init ./hello` 即可生成 `go.work` 文件并初始化工作区，这里将指定模块目录 `./hello` 添加到工作区，多个模块目录之间用空格分隔。

```text
go 1.27

use ./hello
```

在 `workspace` 目录执行 `go run ./hello` 编译并运行 hello 模块。

如果需要扩展 `golang.org/x/example/hello/reverse` 的功能，可以在 `workspace` 目录检出代码：

```bash
git clone https://go.googlesource.com/example
```

然后将模块 `./example/hello`（其中有一个 `go.mod` 文件）添加到工作区：

```bash
go work use ./example/hello
```

添加到工作区的多个模块可以相互找到，不需要使用 `replace` 指令。上一节的 `call-module` 示例也可以用 workspace 管理：`go work init ./hello ./greetings`，无需维护 `replace` 指令。

其它操作：

- 修改 `go.work` 中要求的最低 Go 版本：`go work edit -go=1.27`
- 将模块从工作区中移除：`go work edit -dropuse=./hello`，`-dropuse` 可重复多次，每次指定一个模块目录
