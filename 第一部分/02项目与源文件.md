# 项目与源文件

## 项目命名

按照惯例，项目名（仓库名）使用全小写单词，单词之间以中划线 `-` 分隔。例如：

- [go-ethereum](https://github.com/ethereum/go-ethereum) Ethereum 协议的 Go 实现
- [go-micro](https://github.com/micro/go-micro) Go 微服务开发框架

## `.go` 源文件

### 源文件命名

- 文件名后缀为 `.go`
- 文件名使用全小写单词，单词之间不使用中划线分隔，通常也不使用下划线分隔，所有单词连写在一起（测试文件、平台/架构特定文件除外）
- 测试文件名以 `_test.go` 结尾，`go test` 仅扫描此类文件，编译并运行其中的 `TestXxx`、`BenchmarkXxx`、`ExampleXxx` 等测试函数以及 `FuzzXxx` 模糊测试函数（Go 1.18 引入）。模糊测试文件一般以 `_fuzz_test.go` 结尾，但 `_fuzz` 并非 Go 工具链的强制要求
- 平台/架构特定文件按照 `filename_GOOS.go`、`filename_GOARCH.go` 或 `filename_GOOS_GOARCH.go` 的模式命名，编译时自动选择对应平台/架构的文件。查看所有支持的 `GOOS` 和 `GOARCH` 组合：`go tool dist list`
- 应用程序入口文件通常命名为 `main.go`

### 源文件结构

```text
// 声明该文件所属的包，每个源文件必须属于一个包
package 包名

// 导入依赖包
import (
    "标准库"
    "第三方库"
    "本项目内部包"
)

// 包级 const、var 声明，即包级常量、包级变量的声明
// init() 函数（包的初始化）
// interface、struct 类型定义
// 构造函数 NewXxx()
// struct 方法（按接收者分组）
// 其它工具函数
```

### 注释

- 行注释：以 `//` 开头，注释内容直到行尾结束
- 块注释：位于 `/*` 与 `*/` 之间，注释内容可以跨越多行

注意：

- 注释应解释动机与取舍，即“为什么”，而不是机械复述实现细节（“做了什么”）
- 所有导出的包、常量、变量、函数、类型等应当添加注释，便于调用者理解

## 代码格式化（Format）工具

- [gofmt](https://go.dev/cmd/gofmt/) 官方格式化工具。使用：`gofmt -w .`
- [gofumpt](https://github.com/mvdan/gofumpt) 比 `gofmt` 更严格的格式化工具。安装：`go install mvdan.cc/gofumpt@latest`，使用 `gofumpt -l -w .`
- [golines](https://github.com/golangci/golines) 处理长行（long lines）的格式化。安装：`go install github.com/golangci/golines@latest`，使用 `golines -w .`，可通过 `--max-len` 指定一行的最大长度

上述命令中，`-w` 表示把格式化结果直接写回源文件；`-l` 表示仅列出“格式与工具规则不一致”的文件，常与 `-w` 配合使用。

`golines` 通常作为 `gofmt`、`gofumpt` 的补充使用，而非替代品。

## 代码静态检查（Lint）工具

### go vet

官方静态检查工具，使用：`go vet ./...`

查看完整检查器列表：`go tool vet help`

### staticcheck

staticcheck 通过静态分析发现代码中的错误和性能问题，同时提供代码优化建议，并强制执行编码规范，官方文档：<https://staticcheck.dev/docs/>

安装：`go install honnef.co/go/tools/cmd/staticcheck@latest`

查看 staticcheck 版本：`staticcheck -version`

使用：`staticcheck ./...`，可以像 `go build` 命令那样通过 `-tags` 选项指定构建标签。

### revive

运行速度更快、更严格、可配置、可扩展，是 `golint` 的现代化替代品，官方文档：<https://github.com/mgechev/revive>

安装：`go install github.com/mgechev/revive@latest`

查看 revive 版本：`revive -version`

使用：`revive ./...`

可通过 `-config` 指定配置文件。如果未指定，revive 将尝试使用全局配置文件 `${HOME}/revive.toml`；如果找不到该配置文件，revive 将使用内置的默认代码检查规则集。

### gosec

代码安全漏洞扫描工具，官方文档：<https://github.com/securego/gosec/>

安装：`go install github.com/securego/gosec/v2/cmd/gosec@latest`

使用：`gosec -tests ./...`

### golangci-lint

集成多种检查器的静态分析工具，官方文档：<https://golangci-lint.run/>

安装指南：<https://golangci-lint.run/docs/welcome/install/#local-installation>

常用命令：

- `golangci-lint run`：等价于 `golangci-lint run ./...`
- `golangci-lint run --default=none -E errcheck`：`--default=none` 禁用所有检查器，`-E/--enable <linter>` 启用指定检查器，`-D/--disable <linter>` 禁用指定检查器
- `golangci-lint run dir1 dir2/...`：分析指定的目录
- `golangci-lint run file1.go`：分析指定的文件
- `golangci-lint cache status|clean`：查看缓存状态、清理缓存

配置文件为 `.golangci.yml`，位于项目根目录或用户的 HOME 目录，文档：<https://golangci-lint.run/docs/configuration/file/>

`govet`、`staticcheck`、`revive`、`gosec` 都是 `golangci-lint` 默认或内置支持的 linter，直接在配置文件的 `linters.enable` 里写对应名字即可，无需额外安装。

```yml
version: "2"
linters:
  enable:
    - govet
    - staticcheck
    - revive
    - gosec
```

`gofmt`、`gofumpt`、`golines` 这些代码格式化工具也可以集成到 `golangci-lint` 中：

```yml
version: "2"
formatters:
  enable:
    - gofmt
    - gofumpt
    - golines
```

## 第一个 Go 项目”Hello World“

创建项目：

```bash
mkdir hello-world && cd hello-world  # 项目名为 hello-world，也是项目根目录名
go mod init example.com/hello-world  # 模块初始化，指定模块路径为 example.com/hello-world，将写入模块定义文件 go.mod
```

用 VSCode 打开项目：`code .`（`code` 是 VSCode 的命令行工具），在项目根目录下创建 `main.go` 文件，内容如下：

```go
// 声明 main.go 这个文件所属的包为 main
package main

// 导入标准库的 fmt 包，用于打印输出
import "fmt"

func main() { // 这个 { 不能换行
 // 调用 fmt 包中的 Println 函数
 fmt.Println("Hello, World!")
}
```

运行代码：`go run main.go`，输出：Hello, World!

构建可执行程序：`go build`，生成 hello-world 可执行文件

运行可执行程序：`./hello-world`，输出：Hello, World!

> [!TIP]
> 创建 `main.go` 文件后，VSCode 会提示安装 Go 相关插件，推荐 [官方 Go 插件](https://marketplace.visualstudio.com/items?itemName=golang.go)。安装完成后会自动下载相关工具（如 gopls、dlv 等），按提示确认即可。
