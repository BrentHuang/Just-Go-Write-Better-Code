# 多模块开发

一个模块包含其 `go.mod` 文件所在目录下的所有包，以及该目录下的所有子目录中的包，直到遇到下一个包含 `go.mod` 文件的子目录为止。

一个项目通常只包含一个模块（位于项目根目录下），但 Go 也支持多模块开发。有两种方案：

1. 使用 `go mod edit -replace` 命令将模块路径替换为本地路径
2. 使用多模块工作区：将多个模块添加到一个工作区中

## replace 指令

参考教程：[创建模块](https://go.dev/doc/tutorial/create-module)，[调用模块](https://go.dev/doc/tutorial/call-module-code)

项目结构：

```text
call-module/
├── greetings/          # go mod init example.com/greetings，第一个模块
│   ├── greetings.go
│   ├── greetings_test.go
│   └── go.mod
└── hello/              # go mod init example.com/hello，第二个模块
    ├── main.go
    └── go.mod
```

```go
// greetings/greetings.go
package greetings

import "fmt"

// Hello returns a greeting for the named person.
func Hello(name string) string {
 message := fmt.Sprintf("Hi, %v. Welcome!", name)
 return message
}
```

```go
// greetings/greetings_test.go
package greetings // 单元测试文件位于 greetings 包中，单元测试文件应“靠近”被测试代码

import (
 "fmt"
 "testing"
)

func TestHelloName(t *testing.T) {
 name := "Gladys"
 want := fmt.Sprintf("Hi, %v. Welcome!", name)
 msg := Hello(name)
 if msg != want {
  t.Errorf(`Hello(%q) = %q, want match for %#q`, name, msg, want)
 }
}
```

```go
// hello/main.go
package main

import (
 "fmt"

 "example.com/greetings" // 导入 greetings 模块
)

func main() {
 message := greetings.Hello("Gladys")
 fmt.Println(message)
}
```

模块 `example.com/greetings` 尚未发布到公网时，需要将模块路径替换为本地路径才能访问：

在 `hello` 目录下执行：

```bash
go mod edit -replace example.com/greetings=../greetings
```

该命令会在 `hello/go.mod` 中增加一条 `replace` 指令：`replace example.com/greetings => ../greetings`。

常用操作：

- 在 `greetings` 目录下执行 `go test` 运行测试用例
- 在 `hello` 目录下执行 `go run .` 或 `go run main.go` 编译并运行程序
- 在 `hello` 目录下执行 `go build` 编译可执行程序

## 多模块工作区（multi-module workspaces）

`go work` 是 Go 1.18 引入的工作区模式，用于同时开发多个相互依赖的模块。语法：`go work [init|sync|edit|use|vendor] [arguments]`

工作区文件 `go.work` 包含一组本地模块路径，`go build|run|test` 会同时使用所有工作区模块。

go.work 文件示例：

```text
go 1.26

use (
 ./app
 ./lib
 ./pkg
)
```

常用命令：

- `go work init`：初始化一个新的 `go.work` 文件
- `go work use ./app ./lib`：将本地模块添加到工作区
- `go work sync`：将工作区中解析的依赖版本同步到各模块的 `go.mod` 文件
- `go work vendor`（Go 1.22+）：将工作区中所有模块的依赖复制到 `vendor` 目录，用于离线构建。与 `go mod vendor` 类似，但作用于整个工作区
- `go work edit`：以命令行方式编辑 `go.work` 文件

参考教程：[工作区](https://go.dev/doc/tutorial/workspaces)

项目结构：

```text
workspace/
└── hello/              # go mod init example.com/hello
    ├── main.go
    └── go.mod
```

```go
// hello/main.go
package main

import (
 "fmt"

 "golang.org/x/example/hello/reverse" // 导入 golang.org/x/example/hello 模块的 reverse 包
)

func main() {
 fmt.Println(reverse.String("Hello"))
}
```

在 `workspace` 目录下执行 `go work init ./hello`，会生成 `go.work` 文件：

```text
go 1.26.5

use ./hello
```

在 `workspace` 目录下执行 `go run ./hello` 编译并运行。

如果需要扩充 `golang.org/x/example/hello/reverse` 的功能，可以在 `workspace` 目录下检出代码：

```bash
git clone https://go.googlesource.com/example
```

然后将模块 `./example/hello`（其中有一个 `go.mod` 文件）添加到工作区：

```bash
go work use ./example/hello
```

添加到工作区的多个模块可以相互找到，不需要使用 `replace` 指令。上一节的 call-module 示例也可以用 workspace 管理：`go work init ./hello ./greetings`，更为简便。

其它操作：

- 修改 `go.work` 中最低的 Go 版本要求：`go work edit -go=1.27`
- 将模块从工作区中移除：`go work edit -dropuse=./hello`
