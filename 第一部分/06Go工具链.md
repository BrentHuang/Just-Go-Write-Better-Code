# Go 工具链

## go build

`go build` 用于编译 Go 程序，将源码构建为可执行文件。语法：

`go build [-o output] [build flags] [packages]`

`go build` 编译的基本单元是包，不是源文件。如果编译的是包含 `main()` 函数的 `main` 包，`go build` 会在执行命令的当前目录生成一个可执行文件。如果编译的不是 `main` 包，`go build` 仅做编译检查，不生成任何文件。

Go 默认优先采用静态链接，将程序代码、标准库、依赖和 Go 运行时全部链接进单个可执行文件。但需要说明的是：本地编译默认开启 cgo（`CGO_ENABLED=1`），若程序或其依赖导入了 [net](https://pkg.go.dev/net)、[os/user](https://pkg.go.dev/os/user) 等依赖系统 C 库的包，产物会改为动态链接；设置 Go 环境变量 `CGO_ENABLED=0` 可强制静态链接。交叉编译时 cgo 默认关闭（见下文），产物通常为静态链接。

`packages` 参数通常有以下几种指定方式：

1. 不带参数，编译当前目录下的包：`go build`，等价于 `go build .`
2. 指定一个包。可以是导入路径（如 `example.com/mylib/foo` 或标准库 `net/http`），也可以是指向目录的文件系统路径（以 `./` 或 `../` 开头，或绝对路径）

    ```bash
    go build ./cmd/myapp  # 开头必须加 ./
    ```

3. 指定一个或多个 `.go` 源文件（须来自同一个目录）。`go build main.go` 与 `go build`（不带参数）有本质区别：
   - `go build` 编译的是当前目录下的整个包，包含该包中的所有非测试源文件
   - `go build main.go` 只编译命令行指定的这些文件，Go 会将其视为一个名为 `command-line-arguments` 的虚拟包，同目录下未被指定的源文件都不参与编译。注意：如果指定的文件中引用了同目录其他未指定文件中定义的函数或变量，则会报 `undefined` 错误

    ```bash
    go build main.go  # 仅编译当前目录的 main.go 文件
    go build main.go helper.go  # 多个文件一起编译，可执行文件以第一个源文件名命名
    go build ./cmd/myapp/main.go  # 开头加不加 ./ 都一样，都是相对于当前目录
    ```

4. 使用 `...` 通配符，编译指定路径下的所有包。`go build ./...` 是 CI 中常用的编译检查命令，仅验证项目能否通过编译，不生成可执行文件。`...` 匹配时自动排除以下内容：`vendor` 目录、`testdata` 目录、以 `_` 或 `.` 开头的文件和目录、含有 `go.mod` 文件的目录（即嵌套模块），以及匹配 `go.mod` 中 `ignore` 指令的目录

选项：

- `-o` 指定输出文件的名称或路径
- `-v` 打印编译过程中被处理的包名。注意：只会打印实际被编译的包，如果所有包都已在缓存中且未变化，则没有任何输出。配合 `-a` 可强制打印所有包
- `-x` 打印并执行编译过程中的每个具体命令
- `-n` 打印将要执行的每个具体命令，但不真正执行
- `-a` 强制重新构建所有包，即使它们没有变化
- `-p n` 指定并行编译的任务数量，默认为 `GOMAXPROCS`（通常是 CPU 核心数）
- `-race` 启用数据竞争检测，仅在官方支持竞态检测器的平台上可用（darwin/amd64、darwin/arm64、freebsd/amd64、linux/amd64、linux/arm64、linux/ppc64le、linux/riscv64、windows/amd64 等）
- `-gcflags` 向 Go 编译器传递参数，支持以 `[pattern=]` 包模式前缀控制作用范围。例如 `-gcflags="-N -l"` 仅对命令行指定的包禁用优化和内联，`-gcflags="all=-N -l"` 对所有包（含依赖）生效，`-gcflags="net/http=-N -l"` 仅对 `net/http` 包生效
- `-ldflags` 向 Go 链接器传递参数，同样支持 `[pattern=]` 前缀，例如 `-ldflags="-X main.Version=1.0 -X main.BuildTime=$(date +%s)"` 在链接时注入版本号等信息
- `-tags` 指定构建标签（逗号分隔的列表），用于条件编译
- `-trimpath` 从二进制文件中移除所有文件系统路径，对模块代码，路径会替换为 `module-path@version` 形式；对标准库或 `${GOPATH}` 中的代码，替换为普通导入路径
- `-asmflags` 向汇编器传递参数
- `-gccgoflags` 向 gccgo 编译器/链接器传递参数

### 调试符号

`go build` 保留完整的符号表和调试信息，方便调试和分析 coredump 堆栈。可通过 `-ldflags "-w -s"` 剥离调试符号以压缩体积（约减少 30%～40%，视程序代码与依赖而定），其中 `-w` 移除 DWARF 调试信息，`-s` 移除符号表。

### 注入版本号等信息

编译时注入版本号等信息：先在代码中声明变量，再通过 `-ldflags -X` 注入值。`-ldflags` 的 `-X` 参数在链接时修改变量值，语法为 `-X <包路径>.<变量名>=<值>`，`main` 包写作 `main.<变量名>`，库包写完整导入路径。变量无需导出（大小写皆可），必须初始化为常量字符串或未初始化，否则 `-X` 不生效。

```go
// 声明变量
var (
    Version   = "dev"
    Commit    = "unknown"
    BuildTime = "unknown"
)

func main() {
    if len(os.Args) > 1 && os.Args[1] == "-version" {
        fmt.Printf("Version: %s\nCommit: %s\nBuildTime: %s\n", Version, Commit, BuildTime)
        return
    }
    // ...
}
```

```bash
# 编译时注入值
go build -o myapp -ldflags="-X main.Version=1.2.3 -X main.Commit=$(git rev-parse --short HEAD) -X main.BuildTime=$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

执行 `./myapp -version` 就能看到三行信息：`Version: 1.2.3`、`Commit: abc1234`、`BuildTime: 2026-08-28T10:00:00Z`。

示例代码用 `Version`、`Commit`、`BuildTime`（大写）只是惯例，不是硬性要求。

### 交叉编译

交叉编译只需设置 `GOOS` 和 `GOARCH` 环境变量。例如在 Linux 下编译 Windows 版应用程序：`GOOS=windows GOARCH=amd64 go build`

查看所有支持的 `GOOS` 和 `GOARCH` 组合：`go tool dist list`

### 条件编译

Go 支持两种条件编译方式：

- 平台/架构特定文件
- 构建约束（Build Constraints），即 `//go:build` 注释

#### 平台/架构特定文件

如果源文件名包含操作系统或处理器类型，如 `net_linux.go`、`asm_amd64.s`，`go build` 仅在对应平台/架构下编译这些文件。

命名模式：`<name>_<GOOS>.go`、`<name>_<GOARCH>.go`、`<name>_<GOOS>_<GOARCH>.go`。

#### 构建约束

在源文件最顶端，即在 `package` 声明或包注释（如果有的话）之前放置 `//go:build` 构建约束注释。支持 `&&`（与）、`||`（或）、`!`（非）和 `()` 分组，例如 `//go:build linux || darwin` 表示仅在 Linux 或 macOS 系统编译该文件。相比特定文件命名方式，构建约束的表达能力更强。

Go 1.17 引入的新语法（推荐使用）：

```go
//go:build tag_name

package mypackage

// 仅当编译时激活了 tag_name 标签，此文件才会被编译
```

旧版语法（Go 1.16 及之前）：

```go
// +build tag_name
```

注意：

- tag_name 可以是自定义标签，也可以是内置标签（见下文的描述）
- `//go:build` 注释后面必须保留一个空行，用于将其与包文档注释区分开；构建约束必须出现在源文件顶部附近（即 `package` 声明之前），其前面只允许有空行和其他注释（如版权/许可证声明）

在 `//go:build` 注释中可以通过 `go1.N` 声明编译该文件需要的最低 Go 版本，即仅在满足最低 Go 版本要求时才编译：

```go
//go:build go1.22

package mypackage

// 仅当 Go 版本 >= go1.22 时才会编译该文件
```

`go build` 命令的 `-tags` 选项用于激活自定义构建标签，多个标签用逗号分隔：`go build -tags="tag1,tag2"`。

`-tags` 仅声明哪些标签处于激活状态，标签间的逻辑关系则由构建约束表达式定义。例如 `//go:build linux && (amd64 || arm64) && !cgo` 表示仅在 Linux + amd64/arm64 且未开启 cgo 时编译。

除了通过 `-tags` 选项激活的自定义标签外，构建系统还会自动设置以下内置标签，无需手动指定：

- `GOOS` 和 `GOARCH`：当前构建的目标操作系统和架构，如 `linux`、`amd64`
- 架构特性：如 `amd64.v2`、`arm64.v8.0` 等，由 `GOAMD64`、`GOARM64`（Go 1.23 引入）等环境变量决定
- `unix`：当 `GOOS` 为 Unix 类系统（Linux、macOS 等）时自动设置
- `gc` 或 `gccgo`：当前使用的编译器类型
- `cgo`：当 cgo 启用时自动设置。本地编译默认启用（`CGO_ENABLED=1`），交叉编译默认禁用（`CGO_ENABLED=0`），可通过 `CGO_ENABLED` 环境变量显式控制
- `go1.N`：从 `go1.1` 到当前 Go 版本之间的每个 `go1.x` 标签，如当前为 `go1.27`，会自动激活 `go1.1` 到 `go1.27` 的全部标签

查看指定构建标签后生效的文件列表：`go list -f '{{.GoFiles}}' -tags="tag1,tag2"`

示例：

```text
demo/
├── db_mysql.go
├── db_redis.go
├── go.mod
└── main.go
```

```go
// main.go
package main

import "fmt"

func main() {
 fmt.Println(db())
}
```

```go
// db_redis.go
//go:build redis

package main

func db() string {
 return "redis"
}
```

```go
// db_mysql.go
//go:build mysql

package main

func db() string {
 return "mysql"
}
```

不加 `-tags` 时 `db_redis.go` 和 `db_mysql.go` 均不会编译，添加对应标签后才会编译：

```bash
go build
./main.go:8:14: undefined: db

go build -tags="mysql"
# 运行应用程序输出：mysql

go build -tags="redis"
# 运行应用程序输出：redis
```

## go run

`go run` 在临时目录中编译并立即运行 Go 程序，常用于开发过程。语法：

`go run [build flags] [-exec xprog] package [arguments...]`

`-exec xprog` 指定用于执行编译产物的程序，如通过模拟器运行交叉编译出的二进制。

`package` 参数通常有以下几种指定方式：

1. 指定当前目录 `.`，当前目录必须是一个 `main` 包，且其中存在 `main()` 函数，否则报错

    ```bash
    go run .
    ```

2. 指定一个 `main` 包，且其中存在 `main()` 函数：可以是导入路径（如 `example.com/mylib/cmd/myapp`），也可以是指向目录的文件系统路径（以 `./` 或 `../` 开头，或绝对路径）

    ```bash
    go run ./cmd/myapp  # 开头必须加 ./
    go run example.com/mylib/cmd/myapp
    ```

3. 指定一个或多个包含 `main()` 函数的 `.go` 源文件（须来自同一个目录）。注意：此时 `go run` 只编译这些指定的文件，若某个文件引用了同目录其他未指定文件中定义的函数或变量，则会报 `undefined` 错误

    ```bash
    go run main.go  # 仅编译运行当前目录的 main.go 文件
    go run main.go helper.go  # 多个文件一起编译运行
    go run ./cmd/myapp/main.go  # 开头加不加 ./ 都一样，都是相对于当前目录
    ```

`go run` 接受的选项与 `go build` 基本相同。与 `go build` 不同，`go run` 默认不生成调试器信息（不生成 DWARF 调试信息和符号表），以缩短编译时间。

### 向程序传递参数

向程序传递参数：`go run . arg1 arg2`

代码中可通过 `os.Args`（`[]string` 类型）获取参数：

```go
// go run . 1 2 3
func main() {
 fmt.Println(len(os.Args))                     // 4
 fmt.Printf("the first arg: %v\n", os.Args[0]) // 与 C 语言类似，第一个参数是应用程序的路径

 for i := 1; i < len(os.Args); i++ {
  fmt.Println(os.Args[i]) // 1 2 3
 }
}
```

## go clean

`go clean` 用于清理两类产物：包源码目录中手动执行 `go build` 或其他工具（如 [SWIG](https://swig.org/?lang=zh)）遗留的目标文件，以及构建缓存、模块缓存、测试缓存、模糊测试缓存等各类缓存。语法：

`go clean [flags] [packages]`

`packages` 参数指定要清理哪些包的源码目录，用法与 `go build` 的 `packages` 参数一致，如 `go clean ./...` 清理整个项目。不带参数时，默认清理当前目录的包，等价于 `go clean .`；只有指定了 `-cache`、`-testcache`、`-modcache`、`-fuzzcache` 等缓存标志时，才改为清理对应缓存、不清理包源码目录。缓存标志与 `packages` 参数互斥，同时指定会直接报错。

选项：

- `-x` 打印并执行清除命令
- `-n` 打印将要执行的清除命令，但不真正执行
- `-i` 清理 `go install` 安装到本地的归档文件（`.a`）或可执行文件
- `-r` 递归清理：对参数指定的包（不带参数时为当前目录的包）及其所有依赖包（含间接依赖）都执行同样的清理
- `-cache` 清理整个构建缓存，强制下一次构建时重新编译所有内容
- `-modcache` 清理整个模块下载缓存（`${GOMODCACHE}` 目录），包括已解压的依赖源码，下次构建时重新下载依赖
- `-testcache` 使构建缓存中的测试结果全部失效，强制重新运行测试
- `-fuzzcache` 清理构建缓存中用于模糊测试的缓存文件，不含 `testdata` 目录下的语料（corpus）

## go doc

Go 中注释即文档，`go doc` 用于打印从源码注释中提取的文档内容。语法：

`go doc [doc flags] [package|[package.]symbol[.methodOrField]]`

`go doc` 接受零个、一个或两个参数：

- 不带参数时，打印当前目录下包的文档，等价于 `go doc .`
- 带一个参数时，参数可以是包路径、符号（当前包内），或 `[包.]符号[.方法/字段]` 的形式，如 `json.Number`、`json.Number.Int64`
- 带两个参数时，第一个是包路径，第二个是该包中的符号，或带方法/结构体字段的符号

包路径既可以是包的完整导入路径，也可以是导入路径的后缀（如 `json` 是 `encoding/json` 的简写），还可以用文件系统路径定位包（如以 `./` 或 `../` 开头的相对路径，或绝对路径）。

示例：

- `go doc fmt`
- `go doc fmt.Printf`、`go doc fmt Printf`
- `go doc builtin.append`（内置的 append 函数）、`go doc builtin append`

符号匹配时大小写规则不同：小写字母参数忽略大小写、大写字母参数精确匹配，因此 `go doc json.encoder` 与 `go doc json.Encoder` 效果相同。

查看项目内部文档：

```bash
go doc ./greetings  # 相对路径，指向包
go doc ./greetings.Hello  # 包.符号
cd ./greetings && go doc Hello  # 当前包内的符号，大写开头不会被当作包路径
```

日常开发中，更常用的做法是直接访问 Go 官方包网站 <https://pkg.go.dev/> 在线查阅包文档，包括已发布的第三方库文档。

## go fix

`go fix` 用于扫描指定包中的 Go 源文件，将过时的 API 调用重写为新的 API 调用，或将代码更新为更现代的语言特性。语法：

`go fix [build flags] [-fixtool prog] [fix flags] [packages]`

在项目根目录执行 `go fix ./...` 将自动完成整个项目的迁移。

选项：

- `-diff` 以 unified diff 格式显示将要进行的修改，不实际写入文件

参考：[gofix 博客](https://go.dev/blog/gofix)

## go generate

`go generate` 用于代码自动生成，如 `String()` 方法、mock 实现、protobuf 代码等。它不会在 `go build` 时自动运行，需要手动触发。语法：

`go generate [-run regexp] [-skip regexp] [-n] [-v] [-x] [build flags] [file.go... | packages]`

`go generate` 扫描指定文件或包中的 Go 源文件，查找 `//go:generate` 注释，并在源文件所在目录下执行注释中声明的命令。

`//go:generate` 注释语法：

```go
//go:generate command argument...

```

命令中可以使用 `go generate` 预设的环境变量，如 `$GOFILE`（当前文件名）、`$GOLINE`（指令所在行号）、`$GOPACKAGE`（当前包名），以及用于表示字面量 `$` 的 `$DOLLAR`。

示例：

- `//go:generate stringer -type=MyType`：为类型生成 `String()` 方法
- `//go:generate moq -out mock.go . MyInterface`：为接口生成 mock 实现
- `//go:generate protoc --go_out=. --go_opt=paths=source_relative *.proto`：为 .proto 文件生成 Go 代码
- `//go:generate enumer -type=MyEnum`：为枚举类型生成辅助方法

```go
// color.go
package main

//go:generate stringer -type=Color -output=color_string.go

type Color int

const (
 Red Color = iota
 Green
 Blue
)
```

[stringer](https://pkg.go.dev/golang.org/x/tools/cmd/stringer) 是 Go 官方 [x/tools](https://pkg.go.dev/golang.org/x/tools) 仓库中的一个常用代码生成工具，需要单独安装：`go install golang.org/x/tools/cmd/stringer@latest`

执行 `go generate ./...` 后生成 `color_string.go` 文件，其中包含 `func (i Color) String() string` 方法。

当一个项目中有多种 `//go:generate` 注释时，可以用 `-run`/`-skip` 加正则表达式按需筛选要执行或跳过的命令。例如只想重新生成 mock、跳过 protoc：

```bash
go generate -skip 'protoc' ./...
```
