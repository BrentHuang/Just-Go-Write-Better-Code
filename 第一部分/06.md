# Go 工具链

## go build

`go build` 用于编译 Go 程序，将源代码构建为可执行文件。语法：

`go build [-o output] [build flags] [packages]`

`go build` 编译的基本单元是包（不是单个源文件）。如果编译的是包含 `main()` 函数的 `main` 包，`go build` 会在当前目录生成一个可执行文件。如果编译的不是 `main` 包，`go build` 仅做编译检查，不生成任何文件。

Go 默认采用静态链接，将程序代码、标准库、依赖、Go 运行时全部链接进单个可执行文件。

`packages` 参数通常有以下几种指定方式：

1. 不带参数，编译当前目录下的包：`go build`，等价于 `go build .`
2. 指定一个包路径，Go 会自动定位到该包并编译。包路径可以是相对路径（以 `./` 或 `../` 开头）或绝对路径

    ```bash
    go build ./cmd/myapp
    ```

3. 指定单个 `.go` 文件。注意：`go build main.go` 与 `go build`（不带参数）有本质区别：
   - `go build` 编译的是当前目录下的整个包，会包含该包中的所有非测试源文件
   - `go build main.go` 则只编译 `main.go` 这一个文件，Go 会将其视为一个名为 `command-line-arguments` 的虚拟包，同目录下的其它源文件不会参与编译。注意：如果 `main.go` 中引用了同目录其它文件中定义的函数或变量则会报 `undefined` 错误

    ```bash
    go build main.go
    go build ./cmd/myapp/main.go  # 加不加开头的 ./ 都一样，都是相对于当前目录
    ```

4. 使用 `...` 通配符，编译指定路径下的所有包。`go build ./...` 是 CI 中最常用的编译检查命令，仅验证项目能否通过编译，不生成可执行文件。`...` 匹配时自动排除 `vendor`、`testdata` 目录以及以 `_` 或 `.` 开头的文件和目录

选项：

- `-o` 指定输出文件的名称或路径
- `-v` 打印编译过程中被处理的包名。注意：只会打印实际被编译的包，如果所有包都已在缓存中且未变化，则没有任何输出。配合 `-a` 可强制打印所有包
- `-x` 打印并执行编译过程中的每个具体命令
- `-n` 打印将要执行的每个具体命令，但不真正执行
- `-a` 强制重新构建所有包，即使它们没有变化
- `-p n` 指定并行编译的任务数量，默认为 CPU 核心数
- `-race` 启用数据竞争检测
- `-gcflags` 向 Go 编译器传递参数，支持以 `[pattern=]` 包模式前缀控制作用范围。例如 `-gcflags="-N -l"` 仅对命令行指定的包禁用优化和内联，`-gcflags=all=-N -l` 对所有包（含依赖）生效，`-gcflags=net/http=-N -l` 仅对 `net/http` 包生效
- `-ldflags` 向 Go 链接器传递参数，同样支持 `[pattern=]` 前缀，例如 `-ldflags="-X main.version=1.0 -X main.buildTime=$(date +%s)"` 在链接时注入版本号等信息
- `-tags` 指定构建标签（逗号分隔的列表），用于条件编译
- `-trimpath` 从二进制文件中移除所有文件系统路径，对模块代码，路径会替换为 `module@version` 形式；对标准库或 GOPATH 中的代码，替换为普通导入路径
- `-asmflags` 向汇编器传递参数
- `-gccgoflags` 向 gccgo 编译器传递参数

### 调试符号

`go build` 保留完整的符号表和调试信息，方便调试和分析 coredump 堆栈。可通过 `-ldflags "-w -s"` 剥离调试符号以压缩体积（约减少 40%），其中 `-w` 移除 DWARF 调试信息，`-s` 移除符号表。

### 注入版本号等信息

编译时注入版本号等信息：先在代码中声明变量，再通过 `-ldflags -X` 注入值。`-ldflags` 的 `-X` 参数在链接时修改变量值，语法为 `-X <包路径>.<变量名>=<值>`。

```go
// 声明变量
var (
    Version   = "dev"
    Commit    = "unknown"
    BuildTime = "unknown"
)

func main() {
    if len(os.Args) > 1 && os.Args[1] == "-version" {
        fmt.Printf("Version: %s\nCommit: %s\nBuildTime: %s\n", Version, Commit, BuildTime)
        return
    }
    // ...
}
```

```bash
# 编译时注入值
go build -ldflags="-X main.Version=1.2.3 -X main.Commit=$(git rev-parse --short HEAD) -X main.BuildTime=$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

执行 `./myapp -version` 就能看到类似“Version: 1.2.3 / Commit: abc1234 / BuildTime: 2026-08-28T...”的信息。

### 交叉编译

交叉编译只需设置 `GOOS` 和 `GOARCH` 环境变量。例如在 Linux 下编译 Windows 版可执行文件：`GOOS=windows GOARCH=amd64 go build`

查看所有支持的 GOOS 和 GOARCH 组合：`go tool dist list`

### 条件编译

Go 支持两种条件编译方式：

- 平台/架构特定文件命名
- 构建注释（build constraints）

#### 平台/架构特定文件命名

如果源文件名包含操作系统或处理器类型，如 `net_linux.go`、`asm_amd64.s`，`go build` 仅在对应平台/架构下编译这些文件。

命名模式：`<name>_<GOOS>.go`、`<name>_<GOARCH>.go`、`<name>_<GOOS>_<GOARCH>.go`。

#### 构建注释

在源文件最顶端，即在 `package` 声明或包注释（如果有的话）之前放置构建注释，支持 `&&`（与）、`||`（或）、`!`（非）和 `()` 分组，例如 `//go:build linux || darwin` 表示仅在 Linux 或 macOS 下编译该文件。相比特定文件命名方式，构建注释的表达能力更强。

Go 1.17+ 推荐语法：

```go
//go:build tag_name

package mypackage

// 仅当编译时激活 tag_name 标签时，此文件才会被编译
```

旧版语法（Go 1.16 及之前）：

```go
// +build tag_name
```

注意：

- tag_name 可以是自定义标签，也可以是内置标签（见下文的描述）
- 构建注释后面需要保留一个空行

在构建注释中可以通过 `go1.N` 声明编译该文件需要的最低 Go 版本，即仅在满足最低 Go 版本要求时才编译：

```go
//go:build go1.22

package mypackage

// 仅当 Go 版本 >= 1.22 时才会编译该文件
```

`go build` 命令的 `-tags` 选项用于激活自定义编译标签，多个标签用逗号分隔：`go build -tags="tag1,tag2"`。

`-tags` 仅声明哪些标签处于激活状态，标签间的逻辑关系则由构建注释定义。例如 `//go:build linux && (amd64 || arm64) && !cgo` 表示仅在 Linux + amd64/arm64 且未开启 cgo 时编译。

除了通过 `-tags` 选项激活的自定义标签外，构建系统还会自动设置以下内置标签，无需手动指定：

- `GOOS` 和 `GOARCH`：当前构建的目标操作系统和架构，如 `linux`、`amd64`
- 架构特性：如 `amd64.v2`、`arm64.v8.0` 等，由 `GOAMD64`、`GOARM64` 等环境变量决定
- `unix`：当 `GOOS` 为 Unix 类系统（Linux、macOS 等）时自动设置
- `gc` 或 `gccgo`：当前使用的编译器类型
- `cgo`：当 cgo 启用时自动设置。本地编译默认启用（`CGO_ENABLED=1`），交叉编译默认禁用（`CGO_ENABLED=0`），可通过 `CGO_ENABLED` 环境变量显式控制
- `go1.N`：从 `go1.1` 到当前 Go 版本的所有主版本号，如 Go 1.27 下会设置 `go1.1` 到 `go1.27`

查看指定构建标签后生效的文件列表：`go list -f '{{.GoFiles}}' -tags="tag1,tag2"`

示例：

```text
demo/
├── db_mysql.go
├── db_redis.go
├── go.mod
└── main.go
```

```go
// main.go
package main

import "fmt"

func main() {
 fmt.Println(db())
}
```

```go
// db_redis.go
//go:build redis

package main

func db() string {
 return "redis"
}
```

```go
// db_mysql.go
//go:build mysql

package main

func db() string {
 return "mysql"
}
```

不加 `-tags` 时 `db_redis.go` 和 `db_mysql.go` 均不参与编译，添加对应 tag_name 后才会编译：

```bash
go build
./main.go:8:14: undefined: db

go build -tags="mysql"
# 运行可执行程序输出：mysql

go build -tags="redis"
# 运行可执行程序输出：redis
```

## go run

`go run` 在临时目录中编译并立即运行 Go 程序，常用于开发阶段。语法：

`go run [build flags] [-exec xprog] package [arguments...]`

`package` 参数通常有以下几种指定方式：

1. 指定当前目录 `.`，当前目录必须包含 `main` 包，且有 `main()` 函数，否则报错

    ```bash
    go run .
    ```

2. 指定一个包含 `main` 包且有 `main()` 函数的目录，可以是相对路径（以 `./` 或 `../` 开头）或绝对路径

    ```bash
    go run ./cmd/myapp
    ```

3. 指定单个 `.go` 文件，用于运行一个独立的、包含 `main()` 函数的源文件。注意：如果该文件中引用了同目录其它文件中定义的函数或变量则会报 `undefined` 错误

    ```bash
    go run main.go
    go run cmd/myapp/main.go
    ```

`go run` 接受 `go build` 的所有构建选项。

### 向程序传递参数

向程序传递参数：`go run . arg1 arg2`

代码中可通过 `os.Args`（`[]string` 类型）获取参数：

```go
// go run . 1 2 3
func main() {
 fmt.Println(len(os.Args))                     // 4  --包含可执行程序路径
 fmt.Printf("the first arg: %v\n", os.Args[0]) // 与 C 语言类似，第一个参数是可执行程序的路径

 for i := 1; i < len(os.Args); i++ {
  fmt.Println(os.Args[i]) // 1 2 3
 }
}
```

## go clean

`go clean` 用于清理工作目录，移除由 `go build`、`go test`、`go install` 等命令生成的各类文件和目录。语法：

`go clean [flags] [packages]`

`packages` 参数指定要清理哪些包的构建产物，用法与 `go build` 的 `packages` 参数一致，如 `go clean ./...` 清理整个项目。不指定时默认清理当前目录：

- 对于 `main` 包会删除 `go build` 生成的可执行文件
- 对于非 `main` 包则基本无效果，因为没有可执行文件可清理

选项：

- `-x` 打印并执行清除命令
- `-n` 打印将要执行的清除命令，但不真正执行
- `-r` 递归清理被当前包直接导入的包的构建产物
- `-cache` 清理整个构建缓存，强制下一次构建时重新编译所有内容
- `-testcache` 清理所有测试结果缓存，强制重新运行测试
- `-fuzzcache` 清理模糊测试缓存
- `-modcache` 清理模块下载缓存（`${GOMODCACHE}` 下的内容），包括已解压的依赖源码。下次构建时会重新下载依赖

## go doc

Go 中注释即文档，`go doc` 用于打印从源代码注释中提取的文档内容。语法：

`go doc [doc flags] [package|[package.]symbol[.methodOrField]]`

`go doc` 接受零个、一个或两个参数：

- 不带参数时，打印当前目录下包的文档，等价于 `go doc .`
- 带一个参数时，参数可以是包路径、符号名或 `包.符号` 的形式
- 带两个参数时，第一个是包路径，第二个是该包中的符号或方法

`go doc` 不要求输入完整的包路径或严格的大小写，它会自动匹配。例如 `go doc json.encoder` 与 `go doc json.Encoder` 效果相同。注意：小写字母参数在匹配时忽略大小写，大写字母参数则精确匹配。

查看项目内部文档：

<!-- autocorrect-disable -->
```text
# 包路径
go doc ./greetings 
# 包路径.标识符
go doc ./greetings.Hello
```
<!-- autocorrect-enable -->

日常开发中，更常用的做法是直接访问 Go 官方包仓库 <https://pkg.go.dev/> 在线查阅文档，支持搜索包、函数、类型等，并可直接跳转到源码。对于已发布的第三方模块，它会自动抓取并展示其文档，无需手动执行 `go doc` 命令。

## go fix

`go fix` 用于自动修复代码中过时或可疑的构造，并应用修复器（modernizer）提供的改进建议。语法：

`go fix [build flags] [-fixtool prog] [fix flags] [packages]`

`go fix` 会扫描指定包中的 Go 源文件，将过时的 API 调用重写为新的 API 调用，或将代码更新为更现代的语言特性，例如在项目根目录下执行 `go fix ./...` 将自动完成整个项目的迁移。

选项：

- `-diff` 以 unified diff 格式显示将要进行的修改，不实际写入文件。如果 diff 不为空，命令以非零状态码退出

参考：[gofix 博客](https://go.dev/blog/gofix)

## go generate

`go generate` 用于代码自动生成，如 `String()` 方法、mock 实现、protobuf 代码等。它不会在 `go build` 时自动运行，需要手动触发。语法：

`go generate [-run regexp] [-n] [-v] [-x] [build flags] [file.go... | packages]`

`go generate` 扫描指定文件或包中的 Go 源文件，查找 `//go:generate` 注释，并在源文件所在目录下执行注释中声明的命令。

`//go:generate` 注释语法：

```go
//go:generate command argument...

```

注意：

- 行首不能有空格，`//go` 之间不能有空格

示例：

- `//go:generate stringer -type=MyType` 为类型生成 `String()` 方法
- `//go:generate moq -out mock.go . InterfaceName` 为接口生成 mock 实现
- `//go:generate protoc --go_out=. --go_opt=paths=source_relative *.proto` 从 protobuf 生成 Go 代码
- `//go:generate enumer -type=Status` 为枚举类型生成辅助方法

```go
// color.go
package main

//go:generate stringer -type=Color -output=color_string.go

type Color int

const (
 Red Color = iota
 Green
 Blue
)
```

`stringer` 是 `golang.org/x/tools` 包中的工具，需要单独安装：`go install golang.org/x/tools/cmd/stringer@latest`

执行 `go generate ./...` 后生成 `color_string.go` 文件，其中有 `Color` 类型的 `String()` 方法。
