# 开发环境

## Go 简介

Go 是 Google 开发的一种静态类型、编译型、并发友好的开源编程语言，官网：<https://go.dev/>。它由 Robert Griesemer、Rob Pike 和 Ken Thompson 于 2007 年设计，2009 年正式对外发布，2012 年发布 1.0 稳定版。设计初衷是解决 Google 内部大规模软件开发中遇到的编译慢、依赖复杂、并发难写等问题。

Go 追求**简洁、高效、实用**，其设计哲学可以概括为：

| 理念 | 体现 |
| --- | --- |
| 简单优先 | 关键字仅 25 个，语法精简，学习曲线平缓 |
| 显式优于隐式 | 无隐式类型转换、无异常机制、错误显式返回 |
| 内置并发 | 协程（Goroutine）与通道（Channel）原生支持并发 |
| 工程化导向 | 统一格式化（gofmt）、内置测试、依赖管理（go.mod） |
| 快速编译 | 编译速度快，适合大型项目 |
| 垃圾回收 | 自动内存管理，降低心智负担 |

典型应用场景：

| 领域 | 代表项目/产品 |
| --- | --- |
| 云原生/容器 | Docker、Kubernetes、containerd |
| 微服务 | 各类 API 网关、服务框架（Gin、gRPC） |
| 网络编程 | 高性能服务器、代理（Traefik） |
| DevOps 工具 | Terraform、Prometheus、etcd |
| 区块链 | Hyperledger Fabric、Go-Ethereum |
| 命令行工具 | kubectl、hugo、cobra 系列 |
| 分布式系统 | Consul、NSQ、NATS |

## 开发环境安装

Go 工具链安装指南：<https://go.dev/doc/install>，安装完成后执行 `go version` 确认工具链版本。

## Go 环境变量命令

- `go env` 列出全部 Go 环境变量，格式为 `VAR='VAL'`
- `go env VAR` 列出指定环境变量的值
- `go env -w VAR=VAL` 设置指定环境变量的值（写入 Go 环境变量配置文件 `${GOENV}`，默认为 `${HOME}/.config/go/env`）
- `go env -u VAR` 移除 `go env -w` 写入的设置，恢复默认值

## 几个主要的 Go 环境变量

### GOROOT

Go 的安装目录，包含标准库源码、编译器、链接器、go 命令、gofmt 等工具，以及语言规范等文档、时区数据等辅助资源。Linux/macOS 系统默认为 `/usr/local/go`。

### GOPATH

Go 传统的工作区根目录，默认为 `${HOME}/go`。自 Go 1.16 默认开启模块模式以来，项目源码可存放于任意目录，`${GOPATH}` 不再承担源码存放职责，转而主要承担工具安装和模块缓存两类职责：

- 工具安装目录：`go install` 安装的可执行程序存放于 `${GOPATH}/bin` 目录（环境变量 `GOBIN` 的默认值）
- 模块缓存：`go get` 下载的模块存放于 `${GOPATH}/pkg/mod` 目录（环境变量 `GOMODCACHE` 的默认值）

上述两个目录也可分别通过环境变量 `GOBIN` 和 `GOMODCACHE` 单独设置。

需将 `${HOME}/go/bin` 加到系统环境变量 `PATH` 中，才能在任意位置直接调用这些第三方工具：

```bash
echo 'export PATH=$PATH:${HOME}/go/bin' >> ~/.bashrc
```

### GOTOOLCHAIN

Go 1.21 引入自动工具链管理机制，由环境变量 `GOTOOLCHAIN` 控制，取值：

- `auto`（默认值）：优先使用本地 `${GOROOT}` 目录安装的 Go 版本；当模块要求更高版本时，自动下载对应版本，存放于模块缓存目录 `${GOMODCACHE}`，形如 `golang.org/toolchain@v0.0.1-go1.21.0.linux-amd64`
- `local`：只使用本地 `${GOROOT}` 目录安装的 Go 版本，不自动下载其它版本，版本不匹配时报错。推荐 CI/生产环境设置 `GOTOOLCHAIN=local`，禁止构建时联网下载
- `path`：优先使用本地 `${GOROOT}` 目录安装的 Go 版本；当模块要求更高版本时，在系统环境变量 `PATH` 中查找该指定版本，找不到则报错，不自动下载其它版本
- `go1.24.1`：强制使用指定版本，首先尝试在系统环境变量 `PATH` 中查找该指定版本，找不到则自动下载，存放于模块缓存目录 `${GOMODCACHE}`。一般用于临时验证、问题排查，例如 `GOTOOLCHAIN=go1.24.1 go build` 临时使用 go1.24.1 版本进行编译

### GOPROXY

设置模块代理 URL，用于加速第三方工具、模块的下载，缓解网络访问问题：

```bash
go env GOPROXY  # 查看当前设置
go env -w GOPROXY="https://goproxy.cn,https://goproxy.io,https://proxy.golang.org,direct"  # 逗号分隔的 URL，从左到右依次尝试
go env -u GOPROXY  # 恢复默认值
```

`GOPROXY` 默认为 `https://proxy.golang.org,direct`，最后的 `direct` 表示直接从源码仓库下载。

## 第三方工具的安装与管理

### Go 命令行补全

使用第三方工具 [posener/complete](https://github.com/posener/complete) 为 Go 子命令添加命令行补全：

```bash
# https://github.com/posener/complete/tree/master
go install github.com/posener/complete/v2/gocomplete@latest
yes | COMP_INSTALL=1 gocomplete  # 卸载：COMP_UNINSTALL=1 gocomplete
```

安装后重新打开 shell 生效。

### delve（dlv）调试器

安装 Go 调试器 delve：

```bash
# https://github.com/go-delve/delve
go install github.com/go-delve/delve/cmd/dlv@latest
```

为 delve 添加命令行补全：

```bash
if ! grep -Fxq 'source <(dlv completion bash)' "${HOME}/.bashrc"; then
    echo 'source <(dlv completion bash)' >> "${HOME}/.bashrc"
fi
```

### 第三方工具的管理

使用第三方工具 [gup](https://github.com/nao1215/gup) 管理通过 `go install` 安装的全局 Go 命令行工具（位于 `${GOBIN}` 目录）：

```bash
# https://github.com/nao1215/gup
go install github.com/nao1215/gup@latest
"${HOME}/go/bin/gup" completion --install  # gup 命令行补全
```

常用命令：

- `gup list`：列出已安装的第三方工具，格式为 `toolname: package-path@version`
- `gup check`：检查第三方工具是否为最新版本，以及是否由当前 Go 版本构建（仅报告，不更新）
- `gup update`：更新所有第三方工具
- `gup update <toolname>`：更新指定工具
- `gup remove <toolname>`：卸载指定工具
- `gup export --output > gup.json`：导出已安装的工具列表到 gup.json 文件
- `gup import --file gup.json`：从 gup.json 文件导入并安装第三方工具
