# 开发环境

## Go 简介

Go 是 Google 开发的一种静态类型、编译型、并发友好的开源编程语言，官网：<https://go.dev/>。由 Robert Griesemer、Rob Pike 和 Ken Thompson 于 2007 年设计，2009 年公开宣布，2012 年发布 1.0 稳定版。设计初衷是解决 Google 内部大规模软件开发中遇到的编译慢、依赖复杂、并发难写等问题。

Go 追求简洁、高效、实用，其设计哲学可以概括为：

| 理念 | 体现 |
| --- | --- |
| 简单优先 | 关键字仅 25 个，语法精简 |
| 显式优于隐式 | 无隐式类型转换、无异常机制、错误显式返回 |
| 内置并发 | 协程（goroutine）与通道（channel）原生支持并发 |
| 工程化导向 | 统一格式化（`gofmt`）、内置测试、依赖管理（模块） |
| 快速编译 | 编译速度快，适合大型项目 |
| 垃圾回收 | 自动内存管理，无需手工分配、释放内存 |

典型应用场景：

| 领域 | 代表项目/产品 |
| --- | --- |
| 云原生/容器 | [Docker](https://www.docker.com/)、[Kubernetes](https://kubernetes.io/)、[containerd](https://containerd.io/) |
| 微服务 | 各类 API 网关、服务框架（[Gin](https://gin-gonic.com/)、[gRPC](https://grpc.io/)） |
| 网络编程 | 高性能服务器、代理（[Traefik](https://traefik.io/)） |
| DevOps 工具 | [Terraform](https://www.terraform.io/)、[Prometheus](https://prometheus.io/)、[etcd](https://etcd.io/) |
| 区块链 | [Hyperledger Fabric](https://www.hyperledger.org/projects/fabric)、[Go-Ethereum](https://geth.ethereum.org/) |
| 命令行工具 | [kubectl](https://kubernetes.io/docs/reference/kubectl/)、[Hugo](https://gohugo.io/)，以及广泛用于构建 CLI 的框架 [Cobra](https://github.com/spf13/cobra) |
| 分布式系统 | [Consul](https://www.consul.io/)、[NSQ](https://nsq.io/)、[NATS](https://nats.io/) |

Go 安装指南：<https://go.dev/doc/install>，安装完成后执行 `go version` 确认安装的 Go 版本。

## go env 命令

- `go env`：列出全部 Go 环境变量，输出格式为 `NAME='VALUE'`
- `go env NAME`：查看指定环境变量的值
- `go env -w NAME=VALUE`：设置指定环境变量的值（写入 Go 环境变量配置文件，路径可通过 `go env GOENV` 查看，默认为 `~/.config/go/env`）
- `go env -u NAME`：移除 `go env -w` 设置的值，恢复默认值

## 常用 Go 环境变量

以下环境变量覆盖日常开发中的大部分配置场景。

### GOROOT

Go 的安装目录，默认为 `/usr/local/go`，其中包含编译器、链接器、`go` 命令等工具链组件，以及 `gofmt` 工具、标准库源码、语言文档和辅助资源。

### GOPATH

Go 传统 GOPATH 模式下的根目录，默认为 `~/go`。自 Go 1.16 默认开启模块模式以来，项目源码可存放于任意目录，`GOPATH` 不再承担源码存放职责，转而主要承担工具安装和模块缓存两类职责：

- 工具安装目录：`go install` 安装的可执行文件存放于 `${GOPATH}/bin` 目录（环境变量 `GOBIN` 的默认值）
- 模块缓存：`go` 命令（如 `go get`、`go build` 等）下载的模块存放于 `${GOPATH}/pkg/mod` 目录（环境变量 `GOMODCACHE` 的默认值），模块的详细说明见本部分「04 模块」

上述两个目录也可分别通过环境变量 `GOBIN` 和 `GOMODCACHE` 单独设置。

需将 `~/go/bin` 加入环境变量 `PATH`，才能在任意位置直接使用这些工具：

```bash
if ! grep -Fxq 'export PATH=$PATH:${HOME}/go/bin' "${HOME}/.bashrc"; then
    echo 'export PATH=$PATH:${HOME}/go/bin' >> "${HOME}/.bashrc"
fi
```

### GOTOOLCHAIN

Go 1.21 引入了工具链（toolchain）管理机制，由环境变量 `GOTOOLCHAIN` 控制。

`go` 命令默认使用当前 `${GOROOT}` 目录中的 Go 工具链，也可以根据 `go.mod`/`go.work` 文件中的 `go` 和 `toolchain` 指令要求，切换到环境变量 `PATH` 中已有的其他 Go 工具链，或者按需下载对应工具链。

`GOTOOLCHAIN` 可接受的配置值如下：

- `auto`（默认值）：优先使用当前 `${GOROOT}` 目录中的 Go 工具链；当模块要求更高版本时，先在环境变量 `PATH` 中查找满足条件的 Go 工具链，找不到则自动下载至模块缓存目录 `${GOMODCACHE}`，形如 `golang.org/toolchain@v0.0.1-go1.21.0.linux-amd64`
- `local`：只使用当前 `${GOROOT}` 目录中的 Go 工具链，不自动下载其他 Go 工具链，版本不满足时报错。如果 CI/生产环境要求构建过程中不得自动下载 Go 工具链，可以设置 `GOTOOLCHAIN=local`
- `path`：优先使用当前 `${GOROOT}` 目录中的 Go 工具链；当模块要求更高版本时，在环境变量 `PATH` 中查找满足条件的 Go 工具链，找不到则报错，不自动下载其他 Go 工具链
- 具体版本号，如 `go1.24.1`：强制使用指定版本的 Go 工具链。先在环境变量 `PATH` 中查找匹配的 Go 工具链，找不到则自动下载至模块缓存目录。一般用于临时验证、问题排查，例如 `GOTOOLCHAIN=go1.24.1 go build` 临时使用 go1.24.1 工具链进行编译
- 具体版本号+auto，如 `go1.24.1+auto`：默认使用指定版本的 Go 工具链；当模块要求更高版本时，仍按 `auto` 规则在 `PATH` 中查找或自动下载更高版本工具链。例如执行 `go env -w GOTOOLCHAIN=go1.24.1+auto` 可将系统默认工具链固定为 `go1.24.1`，同时保留自动升级能力
- 具体版本号+path，如 `go1.24.1+path`：仅在环境变量 `PATH` 中查找匹配的 Go 工具链，找不到则报错，不自动下载其他 Go 工具链

### GOPROXY

设置模块代理 URL，用于加速工具、模块的下载，缓解网络访问问题：

```bash
go env GOPROXY  # 查看当前设置
go env -w GOPROXY="https://goproxy.cn,https://goproxy.io,https://proxy.golang.org,direct"  # 逗号分隔的 URL，从左到右依次尝试
go env -u GOPROXY  # 恢复默认值
```

`GOPROXY` 默认为 `https://proxy.golang.org,direct`，末尾的 `direct` 表示直接从源码仓库下载。

## 第三方工具的安装与管理

Go 官方工具链之外，命令行补全、调试与工具升级等场景通常借助第三方工具完成，以下逐一介绍。

### Go 命令行补全

使用第三方工具 [posener/complete](https://github.com/posener/complete/tree/master) 为 Go 子命令添加命令行补全：

```bash
# https://github.com/posener/complete/tree/master
go install github.com/posener/complete/v2/gocomplete@latest
yes | COMP_INSTALL=1 gocomplete  # 卸载：COMP_UNINSTALL=1 gocomplete
```

安装后重新打开 shell 生效。

Go 官方并未提供内置的命令行补全，`go` 子命令（如 `go build`、`go fix`、`go generate`）的补全依赖此类第三方工具。

### delve（dlv）调试器

安装 Go 调试器 delve：

```bash
# https://github.com/go-delve/delve
go install github.com/go-delve/delve/cmd/dlv@latest
```

为 delve 添加命令行补全：

```bash
if ! grep -Fxq 'source <(dlv completion bash)' "${HOME}/.bashrc"; then
    echo 'source <(dlv completion bash)' >> "${HOME}/.bashrc"
fi
```

### 管理已安装的工具

使用 [gup](https://github.com/nao1215/gup) 管理通过 `go install` 安装的工具（位于 `${GOBIN}` 目录）：

```bash
# https://github.com/nao1215/gup
go install github.com/nao1215/gup@latest  # 安装 gup 工具
"${HOME}/go/bin/gup" completion --install  # gup 命令行补全
```

gup 常用命令：

- `gup list`：列出已安装的工具，格式为 `toolname: package-path@version`
- `gup check`：检查工具是否为最新版本，以及是否由当前 Go 版本构建
- `gup update`：更新所有工具
- `gup update <toolname>`：更新指定工具
- `gup remove <toolname>`：卸载指定工具
- `gup export --output > gup.json`：导出已安装的工具列表到 `gup.json` 文件
- `gup import --file gup.json`：从 `gup.json` 文件导入工具列表并在本地安装
