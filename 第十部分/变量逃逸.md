## 变量逃逸

变量逃逸 (escape) 是在**编译阶段**自动执行的一种内存分配决策机制，指的是本应在栈上分配的局部变量，因为被外部引用而必须在堆上分配的现象。逃逸导致局部变量的生命周期可以超出其局部作用域。

逃逸分析：找到不必要的堆分配进行优化，同时需要权衡大 size 结构体类型的值变量拷贝开销。命令如下：

```bash
go build -gcflags="-m" main.go  # -m 打印编译器的优化决策，包括内联和逃逸分析
# 查看更详细的逃逸位置
go build -gcflags="-m -l" main.go  # -l 禁用内联，避免内联掩盖逃逸，便于观察真实的逃逸分析结果
```

### 堆区

堆（Heap）是一块动态分配的内存空间，由 Go 运行时的内存分配器与垃圾回收器 GC 管理，用于存储生命周期超出当前函数作用域（逃逸）或无法在编译期确定大小的对象。

- 在大多数系统架构上堆向高地址增长
- 一个程序中的所有协程共享同一个堆

堆中的典型存放对象：

- 显式分配：通过 `new()` 或 `make()` 创建且发生逃逸的对象。`new()` 本身不决定变量是在堆上还是在栈上分配，完全由逃逸机制决定。一个没有逃逸的 `new(T)` 返回的指针可能指向栈。`make()` 用于映射、通道时总是在堆上分配，因为 Go 运行时需要跨协程管理它们。`make([]T, ...)` 创建的切片的引用头在栈上分配，底层数组是否在堆上分配取决于逃逸机制
- 闭包捕获的变量：被闭包引用而其生命周期需要延长时，会逃逸到堆
- 大 size 对象：无论是否逃逸，过大的对象会直接在堆上分配，以避免栈溢出。具体阈值是编译器实现细节，不同版本可能不同
- sync.Pool 中 New 函数返回的对象：在使用 `sync.Pool` 时，`New` 函数返回的对象会逃逸到堆上，sync.Pool 的目的就是复用这些逃逸到堆上的对象

```go
// 无论是否逃逸，过大的对象会直接在堆上分配，以避免栈溢出
func bigArray() {
 var a [1000000]int
 for i := range a {
  a[i] = i
 }
}

func main() {
 bigArray()
}
```

`go build -gcflags="-m -l" main.go` 分析打印如下：

```text
# command-line-arguments
./main.go:5:6: moved to heap: a
```

用 `new()` 分配的内存也可能不在堆上：

```go
// 当 g() 调用返回时，变量 *y 将是不可达的，也就是说可以马上被回收的。因此，*y 并没有从函数 g() 中逃逸，编译器可以选择在栈上分配 *y 的存储空间，虽然这里用的是 new()
func g() {
 y := new(int)
 *y = 1
}

func main() {
 g()
}
```

`go build -gcflags="-m -l" main.go` 分析打印如下：

```text
# command-line-arguments
./main.go:5:10: new(int) does not escape
```

Go 不存在“栈变量”和“堆变量”的语法区分，开发者无法指定变量分配在堆上，只能由编译器说了算。

### 变量逃逸常见场景

#### 返回局部变量的指针（最常见）

函数返回了局部变量的地址，该指针变量在函数调用结束后仍需使用，其指向的栈变量必须逃逸到堆。

优化策略：返回值而不是指针。如果返回的结构体较大，返回指针虽然导致逃逸，但避免了值拷贝的大量内存复制开销，此时逃逸反而可能提升性能。

```go
func escape() *int {
 v := 100 // 逃逸到堆
 return &v
}

func main() {
 p := escape()
 fmt.Println(*p)
}

// # command-line-arguments
// ./main.go:8:2: moved to heap: v
// ./main.go:14:13: ... argument does not escape
// ./main.go:14:14: *p escapes to heap
```

#### 被闭包引用

闭包引用了外部函数的局部变量，该变量的生命周期被延长至闭包存活期，必定逃逸到堆。

```go
func closure() func() int {
 x := 10 // 逃逸到堆
 return func() int { return x }
}

func main() {
 f := closure()
 fmt.Println(f())
}

// # command-line-arguments
// ./main.go:9:9: func literal escapes to heap
// ./main.go:14:13: ... argument does not escape
// ./main.go:14:15: f() escapes to heap
```

#### 发送指针到通道

往通道里发送指针，编译器不确定接收方何时取走，该指针指向的变量会逃逸到堆。

```go
var c = make(chan *int)

func send() {
 v := 5 // 逃逸到堆
 c <- &v
}

func main() {
 go send()
 p := <-c
 fmt.Println(*p)

 time.Sleep(3 * time.Second)
}

// # command-line-arguments
// ./main.go:11:2: moved to heap: v
// ./main.go:18:13: ... argument does not escape
// ./main.go:18:14: *p escapes to heap
```

#### 将局部变量存储到全局指针

```go
var global *int

func store() {
 x := 15 // 逃逸到堆
 global = &x
}

func main() {
 store()
 fmt.Println(*global)
}

// # command-line-arguments
// ./main.go:10:2: moved to heap: x
// ./main.go:16:13: ... argument does not escape
// ./main.go:16:14: *global escapes to heap
```

#### 将 值类型/指针类型 存入接口

```go
type User struct {
 Name string
 Age  int
}

func f() any {
 var i any
 u := User{Name: "alice", Age: 18} // 栈上的局部变量
 i = u                             // 将值类型 u 赋值给接口，接口的 data 指针指向 u 的副本，Go 会在堆上分配 u 的副本并将 data 指针指向它
 return i
}

func g() any {
 var i any
 u := User{Name: "alice", Age: 18}
 i = &u // 将 u 的指针赋值给接口，接口的 data 指针指向变量 u 本身。如果 i 的生命周期超过了 u 的栈帧（例如被返回），那么通过 data 指针访问 u 将是不安全的。因此，即使 i 存储的是指针，只要 i 本身“活”得比 u 久，编译器仍然会判定为逃逸。为了安全，u 也会被迁移到堆上。
 return i
}

func main() {
}

// # command-line-arguments
// ./main.go:11:6: u escapes to heap
// ./main.go:17:2: moved to heap: u
```

#### fmt 包等反射参数（最常见的意外逃逸）

fmt、json、reflect 等接收 `interface{}`/`any` 参数的函数，通过反射取值，编译器无法追踪值在反射层的流向，导致传入的值逃逸到堆。

```go
func printAll() {
 x := 42
 s := "hello"
 fmt.Printf("x=%d, s=%s\n", x, s) // x 和 s 都逃逸到堆
}

func main() {
}

// # command-line-arguments
// ./main.go:8:12: ... argument does not escape
// ./main.go:8:29: 42 escapes to heap
// ./main.go:8:32: "hello" escapes to heap
```

### 如何减少变量逃逸

减少变量逃逸的核心原则只有一条：让编译器确信，这个变量的生命周期永远不会超出它所在的函数栈帧。

首选泛型，绕过接口装箱：向 `interface{}`/`any` 类型的切片 `[]interface{}` 或 `map[string]interface{}` 中插入基础类型时，必然发生装箱（Boxing）—— 在堆上分配内存来保存该值，让接口的 data 指针指向它。可以使用泛型或定义明确类型的结构体进行替代。

尽可能复用对象（使用 sync.Pool）：如果业务逻辑必须返回接口（例如为了统一处理多种类型），且对象频繁创建，可以使用 sync.Pool 来复用那些逃逸到堆上的对象，减少内存分配、释放。

```go
type User struct {
 Name string
 Age  int
}

var pool = sync.Pool{
 New: func() any { return new(User) },
}

func GetUser() any {
 u := pool.Get().(*User) // 从池中取，而非新建
 u.Name = "Alice"
 return u // 复用已分配的对象，仅装箱指针（不产生新分配），不会逃逸了
}

func PutUser(u any) {
 pool.Put(u.(*User))
}

func main() {
}

// # command-line-arguments
// ./main.go:13:30: new(User) escapes to heap
// ./main.go:22:14: leaking param: u
```
